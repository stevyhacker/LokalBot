Agents and MCP

How do I connect meeting notes via MCP to Claude Code, Codex, and Cursor?

Keep your meeting library on your computer and connect your coding agent through a local, read-only stdio MCP server. LokalBot records and transcribes calls on-device and exposes lokalbot-cli mcp for Claude Code, Codex, Cursor, Windsurf, Gemini CLI, and Antigravity.

Updated November 26, 2026 · 6 min read

Three pieces, all on your computer

A coding agent can only answer "what did we decide about the API migration?" if it can query the call. Cloud notetakers require a bot or cloud upload plus OAuth tokens. A local MCP setup replaces each piece:

  1. Capture without a bot. LokalBot records your microphone and the meeting app's audio on two local tracks. Nothing joins the call.
  2. Transcribe and index on-device. Fine-tuned Qwen3-ASR, Qwen3.5 4B (LokalBot v4), and EmbeddingGemma 2 run locally and store everything in SQLite (39 ms hybrid search).
  3. Expose read-only stdio MCP. The bundled lokalbot-cli mcp command starts a local Model Context Protocol server over stdio. It stays completely off until you enable agent access in Settings.

Step 1: enable read-only access in LokalBot

  1. Install LokalBot on Mac, Windows, or Linux (alpha), let the models finish downloading, and record a test call.
  2. On Mac, open Settings > External Agents, enable Allow external agents to read your LokalBot data, and check Meetings. On Windows and Linux, enable Allow external agents to read your meeting library in Settings > Privacy & Data.
  3. Choose Install for your coding agent... to install the skill and the lokalbot-cli binary (~/.local/bin on Mac/Linux, %LOCALAPPDATA%\Programs\LokalBot\bin on Windows). Add that folder to your PATH if it isn't there already, then restart your terminal. Apps opened from the Dock or Finder, such as Cursor or Claude Desktop, don't read your shell's PATH, so give them the full binary path shown below.

Step 2: connect your MCP client

Use the one-line CLI commands for Claude Code and Codex:

# Claude Code
$ claude mcp add lokalbot -- lokalbot-cli mcp

# Codex
$ codex mcp add lokalbot -- lokalbot-cli mcp

For Cursor (~/.cursor/mcp.json), Windsurf (~/.codeium/windsurf/mcp_config.json), Gemini CLI (~/.gemini/settings.json), and Antigravity, add the exact same stdio command under mcpServers:

{
  "mcpServers": {
    "lokalbot": {
      "command": "lokalbot-cli",
      "args": ["mcp"]
    }
  }
}

If lokalbot-cli is not on your PATH yet, pass its full binary path (on Mac: /Applications/LokalBot.app/Contents/Helpers/lokalbot-cli). Claude Code and Codex users can also install the LokalBot plugins for /lokalbot:brief and /lokalbot:recall skills, and version 0.14.0 can also read local Antigravity and T3 Code coding sessions alongside Claude Code and Codex in day memory.

MCP tools your agent receives

  • list_meetings and search_meetings: Filter meetings by date or title and run local hybrid search across titles, summaries, and transcripts.
  • get_meeting: Return a meeting's metadata, summary, or transcript as Markdown so the agent pulls only what it needs.
  • ask_library: Ask LokalBot's local model a question across your library and return a compact cited answer (~1,248 characters median) instead of dumping raw transcripts into your agent's context window.
  • get_action_items and list_people: Fetch open actions with your edits applied and people by name (email addresses are never returned).
  • Opt-in screen memory and Files: Separate switches grant read-only access to captured screen text (never pixels) and keyword search over folders you chose under Files (search_files).

Agents without MCP support can call the exact same commands from a shell, such as lokalbot-cli search "pricing decision" or lokalbot-cli brief.

Where your meetings go once an agent reads them

LokalBot never uploads your library, and its default MCP tools are strictly read-only. Changing LokalBot settings or running lokalbot-cli reprocess requires a separate opt-in switch (Allow external agents to change LokalBot settings). Remember that whatever text an MCP tool returns enters your agent's prompt, which Claude Code, Codex, Cursor, Windsurf, or Gemini CLI send to their configured model provider under that provider's terms:

  • Prefer search_meetings and ask_library over pulling full raw transcripts.
  • Enable only the data scopes (Meetings, Files, Screen memory, Personal Context) you want that agent to see, and flip the master switch off anytime to revoke access immediately.

FAQ

Questions about this guide

Does the MCP server work with Cursor, Windsurf, Gemini CLI, and Antigravity?

Yes. Any MCP client that launches a local stdio server works with command 'lokalbot-cli' and args ['mcp']. That covers Claude Code, Codex, Cursor, Windsurf, Gemini CLI, and Antigravity on Mac, Windows, and Linux.

Does the agent receive raw meeting audio or screenshots?

No. The MCP server returns text only: meeting metadata, summaries, transcripts, action items, names, cited answers, and (if explicitly enabled) extracted screen text. It never returns audio files or screenshot pixels.

Can the MCP server edit or delete my meetings?

No. The read-only MCP server cannot edit or delete meetings. Changing settings or reprocessing a meeting via CLI requires a separate opt-in toggle.
