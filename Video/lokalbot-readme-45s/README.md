# LokalBot — 45-second README demo

A two-part version of the README demo: 15 seconds of motion graphics that set up the problem and the promise, including the local AI models that do the work, then 30 seconds of the native app in use (Quick Recall, cited meeting decisions, transcript search, Ask with sources, Today, Timeline, and local autocomplete). 1920×1080, 30 fps, 45 s, with a young male ElevenLabs Eleven v4 narrator. The README embeds the light cut as `Assets/videos/lokalbot-readme-demo.mp4`.

- `index.html` — the HyperFrames composition (pinned CLI `hyperframes@0.8.82`).
- `BRIEF.md`, `STORYBOARD.md`, `SCRIPT.md` — intent, beats and shot list with source ranges, narration cues.
- `voice/elevenlabs_v4.py` — generates the eleven narration lines.
- `prepare_media.sh` — cuts recorded takes into `assets/clips/` and mixes `assets/voice/narration.wav`.
- `make_light.sh` — builds the light cut in `build-light/` (see below).
- Generated media (`assets/clips`, `assets/clips-light`, `assets/voice`, `build-light`, `renders`, `snapshots`) is not committed.

## Footage

The app section reuses the takes filmed for the 30-second cut; `../lokalbot-readme-30s/README.md` and `../lokalbot-readme-30s/filming/` explain how they were recorded from the UI test host with a synthetic demo library. The transcripts, outcomes, the Ask answer and the autocomplete suggestion are fixtures; the footage shows the interface and navigation, not live transcription or model performance.

The offscreen capture draws the selected toolbar segment (Summary or Transcript) as a solid pill with no label, and in the dark transcript take it also draws the toolbar labels black. The composition redraws the selected segment as a labelled capsule on exactly those frames, and in the dark cut covers the transcript take's toolbar with the same toolbar cropped from the meeting take (`toolbar.png`, made by `prepare_media.sh`). Frame ranges were measured on the clips; retimed or re-recorded takes need them measured again.

The motion-graphics section is drawn in the composition. The only piece that imitates the app is the empty Quick Recall field at 14.8–15.6 s, drawn to match the panel so the recorded take can fade in over it.

## Models

The 10–15 s beat lists the default local models, and a chip beside each app headline names the model behind that feature. Names and download sizes come from the app's defaults:

| Role | Model | Source |
| --- | --- | --- |
| Transcription | Qwen3-ASR 1.7B, MLX, 2.5 GB | `TranscriptionEngine.swift` |
| Summaries and chat | Qwen3.5 4B, GGUF Q4_K_M, 2.7 GB | `ModelCatalog.swift` |
| Who spoke | Nemotron 3 (Preview), Core ML, 0.2 GB | `DiarizationModel.swift` |
| Semantic search | Harrier 0.6B, GGUF Q8_0, 0.6 GB | `EmbeddingIndex.swift` |
| Autocomplete | LFM2.5 1.2B Instruct, GGUF, 0.7 GB | `ModelCatalog.swift` |

The chips say which model runs a feature. They do not claim that the fixture transcripts, summaries or answers in the footage came from those models. Check the table again when a default model changes.

## Narration

ElevenLabs Eleven v4 (`eleven_v4`) with the premade male voice Liam (young, American), generated by `voice/elevenlabs_v4.py`. The last line carries the `[warm]` delivery tag, which is not spoken. Each request carries the neighbouring lines as context, and the script spells the name "LocalBot" so it is spoken like "local". Line n04 uses seed 99 because other seeds can read "need it" as "meet it". "Qwen" transcribes as "Quinn", which is how the voice says it. Lines were checked with a local faster-whisper transcript: every line lands inside its beat and no tag is read aloud. The voice id is the second argument to the script; Will (`bIHbv24MWmeRgasZH58o`) is a similar alternative.

## Rebuild

```sh
ELEVENLABS_API_KEY=... python3 voice/elevenlabs_v4.py <voice dir>
TAKES=<takes dir> VOICE=<voice dir> ./prepare_media.sh
npx --yes hyperframes@0.8.82 lint
npx --yes hyperframes@0.8.82 check
npx --yes hyperframes@0.8.82 render --quality high --fps 30 --output renders/video.mp4
ffmpeg -i renders/video.mp4 -i assets/voice/narration.wav -map 0:v:0 -map 1:a:0 -c:v copy -af apad -c:a aac -b:a 128k -ar 48000 -t 45 -movflags +faststart <out>.mp4
```

### Light cut

The same composition with `data-theme="light"` on `#root`, light surfaces, and takes recorded with the app in light appearance: the same `film.sh` runs with `LOKALBOT_CAPTURE_APPEARANCE=light` added to each take's environment. The narration is shared. `make_light.sh` writes a separate project in `build-light/` (a HyperFrames project holds one root composition) that points at `assets/clips-light/`.

```sh
TAKES=<light takes dir> CLIPS=assets/clips-light ./prepare_media.sh
./make_light.sh
(cd build-light && npx --yes hyperframes@0.8.82 check && npx --yes hyperframes@0.8.82 render --quality high --fps 30 --output renders/video.mp4)
```

Mux it with `assets/voice/narration.wav` exactly like the dark cut.

These commands run headless Chrome; this render was made locally with the owner's approval as an exception to `Video/AGENTS.md`'s remote-runner default.
