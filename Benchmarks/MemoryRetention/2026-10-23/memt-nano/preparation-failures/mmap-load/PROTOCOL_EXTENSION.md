# MemT-1.0-Nano additional arm

Prepared before this candidate sees any benchmark case. The original four-arm protocol, inputs, scores and reports remain intact. This is an added configuration, not a retroactive alteration of the original experiment.

Use exactly the existing 120 cases, prompts, source handles, gold labels, known-memory lists, JSON schema and frozen scorer. Keep the 96 English cases primary and the 24 Serbian cases exploratory. Use one greedy completion per case, seed 0, explicit thinking disabled through the native chat template, maximum 1024 generated tokens, and 8192 combined prompt/completion tokens. Do not tune against benchmark outputs. Preserve failures and incomplete responses. Semantic review follows the existing disclosed assistant-review procedure with model names visible.

Source: official `MemTensor/MemT-1.0-Nano` revision `30fe0b22422c4cc4c87475f98db5c8baa5c1a902`. All 27 weight files are pinned by size and SHA-256 in `model.json`; the source files are preserved under `sources/`.

The user selected their Windows RX 6600 XT instead of a paid GPU. The machine has about 8 GB VRAM and 32 GB RAM. The published BF16 checkpoint is 70,223,183,936 bytes, and standard Transformers/bitsandbytes linear replacement leaves 60 GiB of packed expert tensors unquantized. Therefore this arm uses the separately inspectable `nf4_offload.py` adapter. It quantizes every expert gate/up and down projection to NF4 with blocksize 64, no double quantization and no calibration. Compressed experts remain in CPU RAM; selected experts are dequantized on the GPU for the original linear operations. Routing, activation, accumulation order, model layers and native memory blocks are preserved. All dense and memory weights remain BF16. No checkpoint tensor may be missing or silently ignored.

This is an experimental quantization and runtime configuration, not an official GGUF or a matched-precision comparison. Transformers 5.12.1, PyTorch 2.11.0+rocm7.13.0, bitsandbytes 0.50.2 with its documented ROCm 7.14 library override, and lm-format-enforcer at upstream commit `817f944fcc8851917c40300a47f62d1defc3ffc3` replace llama.cpp. The enforcer's released 0.11.3 package has an incompatible tokenizer import; the upstream fix is pinned in `lmformatenforcer-revision.json` before any inference. Enforce the same JSON schema through this library, but disclose that the grammar implementation differs. Timings are diagnostic; do not add this different machine to a speed ranking.

Before benchmarking, validate adapter prefill and single-token execution against an explicit dequantized reference, verify original checkpoint tensor coverage, and run a separate empty-JSON smoke prompt that is not one of the benchmark cases. A failed compatibility or smoke check is not a benchmark result. Freeze runner/adapter hashes, package versions, settings and input hashes before the first benchmark request. Never retry or overwrite an observed benchmark failure.

Windows validation also compares a tiny random native MemT model against the adapter after identical NF4 round-trip weights: full prefill, cached decode, native memory commit and memory read logits must agree. `MIOPEN_FIND_MODE=FAST` selects AMD's documented immediate-mode fallback instead of extended convolution solver searches; this setting is recorded in the runtime identity. Downloads and inference run sequentially because concurrent checkpoint writes saturated the host's system SSD. These preparation changes precede all benchmark responses.

Each case starts with no previous latent-memory state and its full evidence in the prompt, as required by the existing task. The official MemT forward method bypasses the native-memory branch when `memory_state` is absent. Consequently this arm measures the published model's stateless extraction behavior; it does not evaluate the benefit or quality of its native persistent-memory feature. Testing that feature requires a separately designed multi-turn/commit-and-recall experiment.

No rental, publishing, model-default change, driver update or application change is authorized by this extension. Only synthetic inputs are transferred to the user's Windows host.
