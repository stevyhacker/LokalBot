# Windows/Linux meeting search, 2026-11-18

`lokalbot-cli search`, MCP `search_meetings` and Ask in the Windows/Linux port (`LinuxWindows/crates/lokalbot-cli/src/search.rs`) decoded every `transcript.json` and folded every segment on every query. About 65% of a search went to `fold` (decomposition, allocation, splitting and joining whitespace) and about 10% to JSON decoding. Now:

- A byte-level prefilter ([`search/prefilter.rs`](../../../LinuxWindows/crates/lokalbot-cli/src/search/prefilter.rs)) skips transcripts, titles, summaries and segments that cannot contain a query word. A transcript is decoded only when the `"text"` values in its raw bytes may match.
- Text that may match is folded by `fold_fast`, which gives exactly what `fold` gives, one character at a time, with an ASCII shortcut. It hands a text with a capital sigma to `fold`, because lowercasing turns Σ into `ς` or `σ` depending on its neighbours.
- Meeting weights are summed in query order. They used to be summed in a `HashSet`'s order, which changes from run to run. That changed the last bits of the sum, so two meetings matching the same three or more words could swap places between two identical searches. Now they keep recency, as the module documents. With one or two query words the sum never depended on order.

Apart from that tie order, the hits are unchanged. Every query below printed byte-identical hits from both binaries. The tests compare the search with a copy of the old one.

## Setup

- [`library_search_bench.py`](library_search_bench.py) builds the same synthetic library as the macOS benchmark in draft PR 522, with 200 segments per meeting and "telescope checksum" in every 25th meeting. The port reads the same layout. This copy adds one query, an accented word typed without accents.
- The before binary is a release build of `lokalbot-cli` at master e1d8997b. The after binary is a release build of this branch.
- Machine: the OVH Ubuntu box (Ryzen 7 9700X, 8 cores, Ubuntu 24.04), with a load average of about 2.
- CLI rows start a new process per search. MCP rows send repeated requests to one `lokalbot-cli mcp` process and leave out the first one.
- Each number is the median of 7 runs, in milliseconds.

## Where the remaining time goes

These are `perf` samples at 250 meetings:

| Query | Share | Work |
| --- | ---: | --- |
| `telescope checksum` | About 67% | The prefilter's scan of `transcript.json`: about 0.6 ns per byte of the file, or 1.2 ns per byte of its text |
| `telescope checksum` | About 4% | Reading the files (kernel copy) |
| `the`, `budget` | About 20% | The same scan, which passes every file |
| `the`, `budget` | About 20% | Decoding the transcripts that pass (serde and UTF-8 checks) |
| `the`, `budget` | About 18% | Rescanning each segment and matching those that pass |

A word found in most meetings still pays for decoding those transcripts. The scan could record which `"text"` values matched, so the segments would not need a second scan. That would save at most the rescan, and it would rely on the JSON's values lining up with the decoded segments, so it was left out.

## Correctness

The tests are in `search/prefilter.rs` and `search/equivalence_tests.rs`:

- **Old against new.** A copy of `hits` from before this change searches 80 random libraries, with 50 queries each, in all four ways the CLI, MCP and Ask call it: CLI and MCP limits, a small limit with one hit per meeting, and Ask's all-words-optional mode on raw queries and on Ask's own terms. The copy differs only in the summation order above. It also searches a copy of the macOS 0.10.9 upgrade fixture with 305 queries. The libraries cover:
  - accents and case;
  - Greek final sigma;
  - Turkish İ;
  - ß and ẞ;
  - Hangul;
  - CJK;
  - full-width kana;
  - combining marks, including U+0345;
  - short words and substrings;
  - quoted phrases;
  - meetings with no transcript;
  - broken, UTF-16 and byte-order-mark transcripts;
  - JSON written by the app or by hand with `\u` escapes (surrogate pairs included), `\/` and escaped keys.
- **Every scalar.** For all 1.1M scalars, alone and between combining marks, `fold_fast` equals `fold`, and the skeleton equals the skeleton of `fold`'s output.
- **Fuzzing.** The fuzz tests use 200,000 random texts of tricky characters and 20,000 hand-escaped transcripts, with needles cut from the folded text so that about half of them match. Whenever the unmodified `word_range` matcher finds a needle, the prefilter must not skip the text or transcript.
- **Mutation checks.** Two deliberate breaks were each caught by several tests: skipping `\u` escapes instead of decoding them, and turning combining marks into separators.
- **Tie order.** `meetings_that_match_the_same_words_keep_recency_on_every_run` fails with the old summation.

How the port differs from the macOS prefilter:

- The port's `fold` drops every combining mark after decomposing, so U+0345 needs no special case.
- `\u` escapes are decoded rather than making the prefilter give up.
- UTF-16 transcripts never decode in the port, because serde needs UTF-8, so skipping them changes nothing.

## Reproduce

```
cd LinuxWindows
cargo build --release -p lokalbot-cli --bin lokalbot-cli
python3 -I ../Benchmarks/search/LibrarySearchPort/library_search_bench.py \
  --cli before=<old lokalbot-cli> --cli after=<new lokalbot-cli> --meetings 250 --runs 7
```

The script writes its synthetic library, including that library's own agent-access switch, to a temporary folder and deletes it afterwards. It never reads the real library.
