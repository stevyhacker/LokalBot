# Meeting search in the CLI and MCP, 2026-11-18

`lokalbot-cli search` and MCP `search_meetings` used to decode and fold every transcript on every query. Now a byte-level prefilter skips transcripts, titles, summaries and segments that cannot match. Other changes:

- `folded` skips rebuilding text that has no whitespace to collapse.
- The library root is resolved once per search.
- Timestamps are formatted only for the hits returned.

Results are unchanged. Every query below printed byte-identical hits from both binaries, and `LibrarySearchPrefilterTests` compares the search against a copy of the old one.

## Setup

- [`library_search_bench.py`](library_search_bench.py): synthetic meetings with 200 segments each, and "telescope checksum" in every 25th meeting.
- Release builds of `lokalbot-cli` at master e1d8997b ("before") and on this branch ("after"), on one M4 Max.
- **The machine was busy:** other sessions were building and running tests, with load averages of 12–22. Runs alternate between the binaries so both see the same load, but the absolute numbers are noisy. On an idle machine the review measured 445 ms for the first row before this change.
- CLI rows start a new process per search, as an agent running the CLI does. MCP rows send repeated requests to one `lokalbot-cli mcp` process and leave out the first one.
- Each number is the median of 7 runs, in milliseconds.

## Where the remaining time goes

These are samples of a warm MCP process answering the rare-word query at 250 meetings:

| Share | Work |
| ---: | --- |
| About 43% | The prefilter's scan of `transcript.json`, about 2.5 ns per byte |
| About 27% | Loading meeting metadata (`loadAllMeetings`) |
| About 24% | Reading summaries and transcripts |

A word that appears in many segments still pays for decoding those transcripts and for the old matcher on the segments that contain it.

A per-process cache of folded segments keyed by path and modification time was not added. It would save at most the scan and the reads, but it would hold about twice the transcript text in every MCP process (one per agent session), and it would still have to check each file's modification time on every query.

## Reproduce

```
xcodebuild -project LokalBot.xcodeproj -scheme lokalbot-cli -configuration Release \
  -derivedDataPath <dir> -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO build
python3 -I Benchmarks/search/LibrarySearch/library_search_bench.py \
  --cli before=<old lokalbot-cli> --cli after=<new lokalbot-cli> --meetings 250 --runs 7
```

The script writes its synthetic library, including that library's own agent-access switch, to a temporary folder and deletes it afterwards. It never reads the real library.
