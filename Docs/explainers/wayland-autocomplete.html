Autocomplete in your apps, on Wayland

Wayland lets no ordinary app read another's keys or type into it, so LokalBot joins as an input method, the way language input tools do. Suggestions appear in the field itself. Tab accepts and Esc dismisses.

Thanks for the update. I wanted to follow up on the migration timeline

Your app

Tells the desktop the text around the caret, and shows the suggestion in its own style, underlined.

⇄

Your desktop

Passes that to the one input method it's running: LokalBot directly on Sway and Hyprland, through IBus on GNOME.

⇄

LokalBot

Asks your Autocomplete model, on this computer unless you chose otherwise, and checks your excluded apps first.

Turn it on
DesktopWhat to do
SwaySettings → Writing → turn on autocomplete. That's all.
Hyprland, OmarchyThe same. Omarchy runs Fcitx 5, and only one input method can run, so LokalBot waits and Settings says so. If you don't use Fcitx 5: systemctl --user disable --now omarchy-fcitx5.service
GNOMETurn it on. With the .tar.gz, run the one command Settings shows. Either way, log out and back in once, then GNOME Settings → Keyboard → Input Sources → + → Other → LokalBot. Choose it in the top bar or with Super+Space.
KDE Plasma, othersNot yet. Settings says so and offers the practice editor.
Which apps
AppResult
GTK 3 and 4Work on Sway and GNOME. On GTK 3 a selection isn't reported, so accepting replaces selected text, as typing does.
Firefox, ChromeWork on Sway. On GNOME they need the Window Calls extension to name the app, and stay quiet without it.
Older Chromium, ElectronNeed --enable-wayland-ime, according to their documentation. Not tried.
Qt 5, X11 appsNo suggestions. Typing is unaffected.
Terminals, passwordsRefused.
What it reads and keeps
  • While a text field has focus, the desktop hands LokalBot up to 4,000 bytes around the caret. In a password field, a terminal, an excluded app or one it can't name, that text is dropped unused and nothing is suggested.
  • On Sway and Hyprland it sees your keys only while a suggestion shows. On GNOME it's asked about every key in a text field while it's your input source. Neither the keys nor the text are kept or logged.
  • It stores only encrypted examples you accepted in identified documents, for 30 days, and estimated counts. Suggestions come from the local model or a server you approved. Full details are in PRIVACY.md.
Limits
  • Using Fcitx or IBus for Chinese, Japanese or Korean? On Sway and Hyprland only one input method can run, so LokalBot steps aside. On GNOME you switch between input sources.
  • Tried on headless Sway 1.9 and GNOME Shell 46 with stand-in suggestions, not on real desktops with a real model. Hyprland itself hasn't been run.
