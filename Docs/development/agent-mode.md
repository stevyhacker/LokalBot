# Agent Mode — an embedded coding agent on your selected Main LLM

Part of the [development guide](../../DEVELOPMENT.md).

- **A coding agent in the sidebar:** the **Agent** section embeds the pi coding agent, preconnected to the same local Main LLM through an OpenAI-compatible shim — a coding agent running on your own GGUF (or whichever backend you configured). A persistent task list supports search, rename, pin, archive, and restore, groups tasks by day, and shows each task's status; refresh, the runtime check and clearing history are in its … menu and the Agent menu. Browsing saved tasks loads native Pi history without starting inference. Execution is limited to four live runtimes; idle saved tasks can release their runtime when another starts.
- **Conversation workspace:** a new task shows a heading, one line saying what the agent may do at the current access level, the composer mid-page and the starters; once it has a conversation the composer docks at the bottom. `AgentTranscriptLayout` (`Agent/AgentPresentation.swift`) regroups the transcript for reading without reordering it: while a turn runs, the agent's words show in full, each run of tool steps folds to one line that opens to a row per step, and the running step shows live; a finished turn folds its work into one "N steps" line above its answer, which carries a Changed files card (Open, Show in Finder) and Copy, Retry and More. Notices are never folded. `AgentStepWording` names each step from its tool and arguments ("Searched meeting library"); a `lokalbot-cli` call gets a name only when it is a single plain call, and any other command shows its text. The task's status (`AgentTaskStatus`) shows beside its title in the toolbar and on its list row. An approval is one card above the composer (`AgentApprovalPresentation`): a question naming the target (Create or Replace from a file-exists check), where the file is, a preview that opens in full, a count when several wait, the full path as a caution outside the working folder or inside LokalBot's own data, and where the result goes with a remote model. Deny sits apart from **Allow once** and, where `canPersistApproval` allows it, **Allow writes/edits for this task**. The results inspector lists changed files, steps and sources, and previews recorded output with copy and local export. Copy, edit as follow-up, review and retry, and branch from message preserve the original conversation and do not undo completed actions.
- **Composer and context:** drag in files or use the context menu and `@` picker to attach UTF-8 documents, text-layer PDFs, meetings, and separately authorized saved moments. Sources are reread on send, with limits of 10 attachments and 60,000 total characters. Explicitly selected meetings are attached as summary/transcript text; screen sources include retained text and notes, never pixels. The composer has three controls: attach, the working folder, and one access chip named for what the agent does on its own (**Asks first**, **Reads any file**, **Edits any file**, **Full access**). Its list holds the four `AgentApprovalMode` levels, which apply to every task, then the model with its destination and reasoning. A model that is not on this Mac also shows under the composer.
- **Follow-ups:** while working, the composer shows Stop and Send, and **Send** adds the message to an editable, cancelable host-side queue shown above the composer ("Sends when done"). **Send now** on a queued message takes it out of the queue and sends it as a Pi steering message, or as an ordinary message when the agent is idle (`sendQueuedNow`); a rejected one returns to its place. Stop and app relaunch pause the queue. Failed sends retain their draft and attachments for review.
- **Navigation:** ⌘N creates a task, ⌘⇧F searches tasks, ⌘⌥←/→ moves between tasks, ⌘F finds in the current conversation, ⌘L focuses the composer, and ⌘⌥B toggles results. Agent actions and tasks also appear in Quick Recall when ⌘K opens it from the Agent screen. Text zoom is available in the Agent menu.
- **Persistence:** `agent/sessions/tasks.json` stores task metadata, drafts, queued follow-ups, and attachment references alongside native Pi JSONL conversations. The latter contain the context actually sent. Archiving preserves both; **Clear saved Agent history** removes both after confirmation. A branch copies the chosen native conversation ancestry to an independent file; it neither replays tools nor rolls back files.
- **Pi's own network behavior is disabled:** pi runs with `--offline`, version checks and crash reporting disabled. Enabling Agent Mode downloads its runtime once — a checksum-verified Bun release from GitHub plus the pi package from npm, pinned by a lockfile bundled with LokalBot. Bun's transpiler cache, pi's compile cache, and jiti's extension cache are off (`PiLaunchPlanner`), so no compiled copy of pi or the approval extension is kept outside that runtime. LLM requests stay local with the built-in backend; an approved remote Ollama or OpenAI-compatible endpoint receives agent context when selected.
- **System prompt:** `LokalBot/Resources/pi/system-prompt.md` replaces pi's coding-agent prompt (`--system-prompt`), and the Windows and Linux copy in `lokalbot-agent/resources` must stay identical (a Rust test compares them). It tells the model what LokalBot remembers and which `lokalbot-cli` commands read it; the bundled `lokalbot-library` skill has the details. Keep that skill's frontmatter valid YAML, with no `: ` inside the description, because pi drops a skill it cannot parse without an error. Before each run the extension adds an `environment` section with the local date and time zone, whether the folder is the Agent Workspace or one the user chose (`LOKALBOT_AGENT_WORKSPACE_KIND`), and the model and where it is served. Pi folds a changed section into the leading system message, which small local models' chat templates require, so a resumed task never gets a second system message.
- **Workspace boundary:** new tasks use a sibling working directory outside the private library. Saved tasks rooted inside the library retain their history and drafts but cannot execute. Raw reads of protected library, runtime, and session paths enter the tool-approval flow when a broader parent directory is selected; the selected approval mode still applies.
- **You approve sensitive access:** the extension's gate is an allowlist. A read inside the selected workspace and outside the private library is the only tool call the extension lets through without raising a request. The host then answers one kind of raised request by itself at every level, the default included, when the model runs on this Mac: a read-only lookup of the user's own library, as `AgentApprovalPolicy.isLibraryLookup` defines it (one `lokalbot-cli brief`, `list`, `get` or `search` call of plain and quoted words, with only the options listed in `lookupOptions`, optionally followed by `2>&1` and `| head`/`| tail` with a line count, from the task's own working folder). A lookup's output is fed to the model, so `modelRunsOnThisMac` is true only while the controller's bound `modelContext` is `.onDevice`; with a server, a subscription plan, or no bound model it is false and the lookup asks, except for a handed-off task (`allowsLibraryLookups`) in the read levels, as before. Anything the policy cannot prove to be a lookup asks. Add an option to `lookupOptions` only when it neither writes nor reaches the network. The extension checks the file pi will open: it resolves the path as pi's file tools do (a leading `@`, `~`, file URLs, Unicode spaces, look-alike names, the session folder), and a path it cannot resolve asks. File and shell calls follow the selected approval mode. Any other tool (an MCP tool, codemode, or one a later Pi release adds) asks with its exact arguments in every mode except **Full access**, which approves every agent tool; it cannot be allowed for the session. Commands, and the arguments of tools without a dedicated preview, exceeding 65,536 JavaScript UTF-16 code units are rejected before approval; the host also rejects incomplete or truncated previews. Approved shell commands run with your macOS user permissions and may access files or the network.
- **Inference redirects:** native buffered/streaming HTTP requests follow redirects only within the original scheme/host/port. The Pi provider uses its own scoped fetch adapter that rejects all redirects and validates the initial origin. Configure a server's final endpoint directly; inference approval does not authorize forwarding prompts or credentials to a different origin.
- **Headless:** `LokalBot --agent "<prompt>"` runs one agent turn from the terminal (see Headless flags). It auto-approves file changes and, when the model runs on this Mac, read-only library lookups like every task, but safely declines other shell and external-read requests because no person is present to review them.
