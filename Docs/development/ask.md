# Ask assistant — conversational Q&A over your library

Part of the [development guide](../../DEVELOPMENT.md).

- **Chat with your meetings:** pressing Return in the **Ask** section sends your question to a conversational assistant over your library — ask what was decided, find action items, or search transcripts in natural language. A small ReAct agent (`ChatAgent`) reuses the selected `TextEngine` and calls tools to ground every answer. With the built-in default it stays on the Mac; an approved remote backend receives the prompt context needed to answer.
- **Tools (pi-agent style, mirroring the CLI):** `search_meetings` (FTS5 keyword + optional semantic search), `list_meetings` (filter by title), and `get_meeting` (read a meeting's summary, or its transcript one 6,000-character window at a time; a cut window names the timestamp to continue from with `from=HH:MM:SS`). The agent picks a tool, reads the observation, then answers — citing meeting titles and dates, and saying so plainly when nothing matches.
- **Limits:** the system prompt ends with the current local time so relative dates resolve. Each turn replays up to 16 recent messages within 12,000 characters, never starting with an answer whose question was cut, and allows six tool calls before a forced answer that must say what it could not check. Apple Intelligence keeps four tool calls and eight messages within 4,000 characters for its small window.
- **Robust protocol:** tools are advertised in the system prompt with the recent-meeting list as ambient context; a tool call is parsed from a JSON object **or** a model's native `name(arg=…)` function-call form (smaller Qwen models emit the latter), with a tolerant fallback to a plain answer so a sloppy reply never hard-fails.
- **Reuses the configured backend:** built-in llama-server by default, or Ollama / OpenAI-compatible / Apple Intelligence / ChatGPT plan / Claude plan — the same Settings → Models choice.
- **Personal Context (personal world model, phase 1):** a message starting with "Remember …" (`RememberIntent`) is saved as a `PersonalClaim` by `PersonalModelController` without a model call; the reply is a receipt turn that stays out of model history. Each question gets a `PersonalContextBuilder` selection (Always use, principles and preferences, then facts and goals sharing words with the question or the previous two user turns, within 2,000 characters) placed after the library overview and before work memory, and the answer records `usedClaimIDs`. Stated claims carry no evidence, so scoped questions get them too. Settings → Personal Context (its own tab, `SettingsTab.personalContext`, `PersonalContextSettings`) edits them; `AppSettings.askMemoryEnabled` gates saving and use. Headless `--chat` builds the same block. After each overnight review, `AppState.learnAboutPerson` (when `personalLearningEnabled` is on) first runs `WorkMemoryPromotion`: Dream goals or projects kept 14+ days become review suggestions. It then runs `PersonalLearning` on that day's own-microphone lines (`ownTurns`: microphone segments attributed to the user, no echo or overlap; plain `local` and `local 1` are one voice; with several numbered voices only one that has 4× the next counts, else the meeting is skipped; a confirmed voice wins) plus typed lines from `PersonalLearning.typedLines`: coding-agent requests and Ask questions, which always go to review. With `personalLearningFromDictation` (off by default; `AppSettings.learnsFromDictation` also needs Ask memory and learning), `DictationCoordinator` hands the raw spoken words of each paste into an identified field to `AppState.keepDictationForLearning` after `CotypingAXHelper.dictationLearningSurface` reads the window title and page address once and `DictationLearningPolicy` applies the nearby-text exclusions (apps, websites, private windows, LokalBot itself, unreadable browser pages). `DictationLearningLog` keeps them sealed with the chat key in `memory/dictation-for-learning.json.enc` (redacted, at most 200, two days); the learning pass reads its day as `.typed(.dictation(app:))` lines, skips ones already read as an agent request, and then deletes the day. Items in the line's language are grounded by word overlap; an item the model translated is compared with `EmbeddingIndex.similarityVectors` (local, never downloads), and uncertain ones become suggestions. Grounded facts and goals are saved as learned, preferences become suggestions, and learned items retract through `DreamStore.evidenceCheck` when their meeting changes. Items marked Share with agents reach external agents only through the separate Personal context grant: `PersonalContextAccessManager` mirrors them into `control/personal-context.json` on every change, and `get_personal_context` / `lokalbot-cli personal-context` rank them with the same `PersonalContextSelection`. See `Docs/designs/personal-world-model-rfc-2026-10-14.md`. Each pass records the day and a SHA-256 `fingerprint` of its non-dictated lines in the personal model's `learnedDays` (60 days); a rebuilt review with the same lines doesn't call the model again. When a learned claim's evidence revision is invalidated, `retractInvalidated` asks `learnedClaimSourceStillQuotes` (that meeting's `ownTurns`, that day's agent requests, or work memory) and re-stamps the claim to the current revision if its quote is still there; otherwise it is retracted.
