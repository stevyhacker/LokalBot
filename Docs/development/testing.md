# Testing

Part of the [development guide](../../DEVELOPMENT.md).

- **Unit** (`LokalBotTests`, in-process):
  ```bash
  xcodebuild -project LokalBot.xcodeproj -scheme LokalBot -destination 'platform=macOS' test
  ```
  Pure-logic coverage — prompt sanitizers, search ranker, model fit, transcript merging, settings codecs, data migration, and the chat agent (tool-call parsing for JSON **and** native function-call forms, the ReAct loop, observation formatters).
  Select an affected class or method with `-only-testing:LokalBotTests/CotypingCoordinatorTests` (replace the class with the relevant test).
  Unit tests never read the checkout or `~/Documents`, because macOS asks each freshly built test host for Documents access. `project.yml` copies the repository files tests check into the test bundle, `Scripts/test/unit-tests.sh` builds outside the checkout (`--derived-data-path` prints where; `LOKALBOT_DERIVED_DATA` overrides it), and real-model cotyping tests read `LOKALBOT_COTYPING_TEST_MODEL` instead of `Vendor/llama-models`.
  A skipped test is not a passed one. `Scripts/test/unit-tests.sh` and the hosted unit job run `Scripts/ci/unit-skips.py` on the result: a run fails when a test skips that `Scripts/ci/unit-skips.json` does not name. That file lists every opt-in test with what it needs (a model folder, a key, a private fixture) and when to run it; the hosted job also fails when a listed test runs or no longer exists, so remove a test from the list in the change that makes it run.
  Unit tests never download models. Their settings turn semantic search on, so `AppState` gives its embedding index `EmbeddingIndex.unavailableEmbedder`; any other test that reaches the real embedder has the model download refused (`UITestRuntime.refuseDownloadInUnitTests`), and the bundle's principal class, `LokalBotTestObservation`, fails that test. Pass `embedder:` to `EmbeddingIndex` when a test needs vectors. `EmbeddingIndexIntegrationTests` uses the real model from its fixture library's `models/` folder.
- **Qwen upgrade parity:** `QwenASREngineTests/testCachedModelTranscriptionMatchesReferenceWhenProvided` uses cached weights from `LOKALBOT_QWEN_TEST_MODEL_DIR` and a `LOKALBOT_QWEN_TEST_REFERENCE` JSON array of `{id, audio, language, text}` records. Use public or synthetic audio, with `text` captured from the previous pinned runtime. It checks the production decode entry point with both repetition policies; `LOKALBOT_QWEN_TEST_REPORT` optionally writes the decoded outputs. Prefix these environment variables with `TEST_RUNNER_` when invoking `xcodebuild` so they reach the test host. Regular unit runs skip this hardware check without a fixture.
- **Qwen forced aligner:** the `testCachedAligner…` tests in `WordAttributionTests` load a downloaded Qwen3-ForcedAligner-0.6B-4bit folder from `LOKALBOT_QWEN_ALIGNER_TEST_DIR` (the app keeps it under `qwen3-asr-models/models/aufklarer/`; add the `TEST_RUNNER_` prefix). They verify the pinned files offline, time a short phrase, and check that MLX's buffer pool stays within `QwenWordAligner.scratchCacheLimit` across segments of different lengths and is empty after a batch. Regular unit runs skip them.
- **Transcription language replay:** `TranscriptionLanguageReplayTests` runs processing's per-track transcription (speaker separation, attribution, cleanup) on copies of saved tracks, once per engine and language listed in a `TEST_RUNNER_LOKALBOT_TRANSCRIPTION_REPLAY_MANIFEST` JSON file (`tracks`, `conditions` of `{engine, language}`, optional `vocabulary` and `contentRange`, and an `output` folder outside the checkout). It uses the downloaded Whisper and Qwen models and writes each run's transcript before (`.raw.json`) and after cleanup. Use it to check how an engine handles a meeting's language and its silent stretches; regular unit runs skip it.
- **Anthropic API:** `AnthropicEngineTests` covers the native Messages API requests offline. `AnthropicLiveTests` sends synthetic text to Anthropic only when `TEST_RUNNER_ANTHROPIC_API_KEY` is set (`TEST_RUNNER_LOKALBOT_ANTHROPIC_MODEL` overrides `claude-sonnet-5-5`): it checks that the meeting-notes schema is accepted, that repeated context is read from the prompt cache, and that streaming completes.
- **Transcription server word times:** `RemoteTranscriptionEngineTests` covers the word-timing request, parsing a recorded MAI-Transcribe-2 reply, the window offset, and the HTTP 400 fallback offline; `WordAttributionTests` covers skipping the aligner when every segment has server word times. `RemoteTranscriptionLiveTests` sends a synthetic two-voice `say` clip to OpenRouter only when `TEST_RUNNER_OPENROUTER_API_KEY` is set (`TEST_RUNNER_LOKALBOT_OPENROUTER_TRANSCRIPTION_MODEL` overrides `microsoft/mai-transcribe-2`) and checks that the returned word times split the two voices.
- **Subscription plans:** `ChatGPTPlanTests` covers the authorization URL, callback and ID-token checks, refresh rotation, revocation, the full loopback sign-in round trip, and the Responses requests and stream errors offline. `ClaudePlanEngineTests` covers the `claude -p` arguments, results, and failures with a fake runner, plus the process runner with `/bin/cat` and `/bin/sleep`. `SubscriptionPlanSettingsTests` covers approvals, presentation, Agent Mode, and settings. `ChatGPTPlanRelayTests` covers the Agent relay over real loopback HTTP with a fake upstream: the key check before the body, the plan route's body rules, token refresh, retry headers, and hang-up and stop cancelling the upstream request. `Scripts/tests/pi-runtime.test.ts` runs a pi tool turn over the Responses API against a fake relay. `ClaudePlanLiveTests` runs the installed, signed-in Claude Code on its plan only when `TEST_RUNNER_LOKALBOT_CLAUDE_PLAN_LIVE=1` is set (`TEST_RUNNER_LOKALBOT_CLAUDE_PLAN_MODEL` overrides `haiku`). `ChatGPTPlanLiveTests` sends Agent Mode's request shapes (a function tool round trip with encrypted reasoning), then runs a real pi tool turn through the relay, on the ChatGPT plan only when `TEST_RUNNER_LOKALBOT_CHATGPT_PLAN_LIVE=1` is set (`TEST_RUNNER_LOKALBOT_CHATGPT_PLAN_MODEL` overrides the first listed model; `TEST_RUNNER_LOKALBOT_AGENT_RUNTIME_ROOT` overrides the installed Agent runtime). It reuses the sign-in LokalBot already holds, since signing in needs a person in a browser; the test build's first Keychain read asks for approval.
- **Email:** `GmailOAuthTests` covers the authorization URL, callback state and scope checks, LokalBot's own client (no secret, its own redirect scheme, sign-in through a stand-in for the sheet, refusing a redirect in any other scheme), client-file import, refreshing with the client that issued the tokens, revocation and the loopback sign-in round trip offline. `GmailSyncTests` runs first and later passes against `FakeGmailServer` (`LokalBotTests/GmailTestSupport.swift`), an in-memory mailbox that answers LokalBot's two kinds of search: qualifying and skipped threads, history replay, expired history, a newly added attendee, window ageing, an interrupted pass, retries, and that every request is a `GET` to Gmail. `EmailScopeTests`, `EmailTextTests`, `EmailStoreTests` and `EmailControllerTests` cover bulk detection, address and charset parsing, HTML conversion, sealed storage and disconnecting.
- **Audio crash probe:** `bash Scripts/tests/audio-recovery-crash.sh` kills a synthetic writer with SIGKILL, removes its growing CAF, and verifies waveform/frame coverage from checkpoints without capture devices or a private library. The hosted unit job also runs it, beside the unit tests.
- **Agent runtime:** `LOKALBOT_PINNED_RUNTIME_ROOT=/path/to/agent-runtime bash Scripts/tests/run-pi-runtime-tests.sh` runs the extension and adapter tests against the pinned runtime. It copies test sources to a temporary folder and uses synthetic loopback services without changing the installed runtime.
- **UI** (`LokalBotUITests`, XCUITest): run the hosted **UI Tests** workflow or another remote Mac runner. `Scripts/test/ui-tests.sh --remote` dispatches the suite; append a test name to select one test. Never use `--foreground` or run UI tests locally on this MacBook. The script checks that the relevant changes are committed and pushed so the remote runner tests the intended revision. It drives a dedicated UI Test Host against a synthetic library under a temporary `LOKALBOT_STORAGE_ROOT`; `LOKALBOT_UI_TEST=1` skips side-effectful subsystems, so the suite never touches the installed production app.
- **Documentation captures:** `Scripts/media/capture-screenshots.sh --stills-only` builds the same isolated host, seeds synthetic data, and renders fixed-density PNGs in-process. This is a capture pass, not the XCUITest suite; see [Docs/guides/screenshot-kit.md](../guides/screenshot-kit.md).
- **README demo GIFs:** `Video/lokalbot-landing-demos/readme_gifs.py` cuts the README's GIFs and stills from the home page's clips in `Website/public/assets/demos`, without launching anything. Those clips are filmed on the isolated host with real input; see [Video/lokalbot-landing-demos/README.md](../../Video/lokalbot-landing-demos/README.md).
- **End-to-end** (`Scripts/test/e2e.sh`): exercises real audio, CoreML transcription, the bundled llama-server, and SQLite via the headless flags; skips flows needing ungranted permissions.
- **Scripts and lint:** `python3 -m unittest discover -s Scripts/tests` covers the CI helpers, seed profiles, trace checker, drift report, the appcast generator, the plugin copies, and the safety of the side-by-side autocomplete scripts; `swiftlint lint --strict --quiet` must exit 0. CI runs SwiftLint 0.65.1 from its official Linux image (`.github/workflows/lint.yml`); install the same version locally to match.
- **Model scenarios:** `LokalBotTests/Fixtures/stub-openai.ts` is an OpenAI-compatible stub (Bun, pinned by `Scripts/ci/fetch-bun.sh`; point `LOKALBOT_TEST_BUN` at it locally) that answers each request by its system-prompt marker (`LokalBotTests/Support/ModelRequestPurpose.swift`) and can truncate, stall, drop, or send malformed or reasoning-heavy replies. `ModelServerScenarioTests` drives the real engine and generators through it. `LokalBotTests/Fixtures/model-recordings/` holds real GLM 5.3 Flash and Qwen3.8 Flash answers to synthetic prompts; `ModelReplayTests` replays them and `ModelBudgetGuardTests` fails when a recorded answer no longer fits our token budgets. The nightly `Model drift` job records fresh answers (OpenRouter, the only two models, at most 40 requests) and uploads them as the `model-recordings` artifact; refresh the committed recordings from that artifact in a normal PR after reading every answer. Drift opens an issue without failing the job. A committed case that got no answer at all (a rejected key, spent credit, a renamed model) fails it and opens its own issue, because that run checked nothing for the case. A pull request from a fork has no key: there the job says so in a notice and records nothing. A nightly or manual run without the key fails.
- **Capture replay:** capture, activity tracking, and meeting detection read every OS boundary through `CaptureEnvironment` (`LokalBot/Services/Capture/`). `ReplayCaptureEnvironment` answers from a trace in virtual time; traces live in `LokalBotTests/Fixtures/capture-traces/` and `CaptureReplayTests` runs the real services on them. Record a trace with a Debug build's `--record-capture`, the Debug menu's **Record Capture Trace**, or `Scripts/test/record-capture/run.sh chrome|safari` (launches a browser and the app — ask first). Traces are scrubbed before they are written, and CI's `check-capture-recordings.py` rejects any unscrubbed trace. **Every escaped capture bug gets a trace (scripted, or reconstructed by hand in scrubbed form) and a replay test that fails with the fix undone.**
- **Day in the life:** `LOKALBOT_APP=<Debug build> LOKALBOT_TEST_BUN=<bun> bash Scripts/test/day-in-the-life.sh` seeds one untranscribed workday (`Scripts/test/seed_demo_library.py --profile full-day`), transcribes it from golden transcripts, writes notes and the digest through the model stub, reviews a meeting boundary, searches meetings and screen text, and runs the health checks (digest coverage at least 60%). It launches the app headless; on failure it keeps the library for inspection. On every PR the unit-test job runs it beside the unit tests, and the `Day in the life (macOS)` check reports its result; the nightly run repeats it with real Parakeet (`--real-asr`). Recorded notes answers quote the golden wording, so the real-ASR run checks the day's word error rate against the golden transcripts (case, punctuation, hyphens, and split or joined compounds ignored; at most 10% across the day's meetings, so one misheard word in a short meeting cannot decide the run) and that the design review's notes finish, instead of the quoted owner. A failed nightly run uploads its library as the `day-in-the-life-real` artifact.
- **UI background shard:** `BackgroundFlowUITests` runs the UI Test Host with its background work on (`LOKALBOT_UI_TEST_BACKGROUND=1`, a replayed trace, file audio, golden transcripts, and the model stub). `Scripts/ci/ui-shards.py` gives it its own `background` shard, and the aggregate XCUITest gate requires it. Hosted CI only, like every UI test.
- **Upgrade fixtures:** the `Upgrade fixtures` workflow seeds a library with each release's own seed script, opens it with that release's signed build on a clean hosted Mac, and uploads the library, defaults, and synthetic test keys. Each stable release run builds its own fixture once the DMG is published; the next release candidate adds it with `Scripts/test/upgrade-fixtures/add.sh <version>` (RELEASING.md step 0). The committed folders in `LokalBotTests/Fixtures/upgrade/` are the list of fixture versions: a dispatch without versions rebuilds them all, and a pull request that changes the generator rebuilds the newest.
- **Nightly:** `.github/workflows/nightly.yml` compares pinned models with their GitHub releases (`Scripts/ci/check-model-pins.py`), and runs model drift, the real-Parakeet workday, and scale checks (a 180-day library, a digest while activity is written, two copies on one library). It never blocks a PR; failures open or update an issue.
- **Health checks:** Debug builds evaluate yesterday at 09:00 (and on the next launch if that was missed) and post a notification that opens the report on failure. `LokalBot --health` runs the same checks on demand. Reports are written to `diagnostics/health/YYYY-MM-DD.{json,md}` in the library. Settings → Diagnostics → System has **Run Health Check Now** and **Export Diagnostics…**.
