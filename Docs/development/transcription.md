# Transcription & speakers

Part of the [development guide](../../DEVELOPMENT.md).

Engines (Settings → Models; CoreML/MLX, in-process, Neural Engine/Metal):

| Engine | Coverage | Notes |
| --- | --- | --- |
| **IBM Granite Speech 4.1** | high-accuracy local ASR | optional |
| **IBM Granite Speech 5.0 2B** (Q8, ~3.12 GB) | English, French, German, Spanish, Portuguese, Japanese | optional; local llama.cpp, vocabulary hints and punctuated output; separate from 4.1 and the English-only 470M TurboCTC model |
| **Parakeet Ultra 0.6B** (CoreML, ~0.63 GB) | 25 European languages | fast multilingual option; separate from existing v2/v3 selections |
| **Parakeet TDT 0.6B v3** | 25 languages, up to ~190× realtime in local benchmarks | fastest local option |
| **Parakeet TDT 0.6B v2** | English only | slightly higher recall |
| **Qwen3-ASR 1.7B** (MLX, ~2.47 GB) | 52 languages/dialects | **recommended**; best Qwen accuracy tier for harder recordings |
| **Qwen3-ASR 0.6B** (MLX, ~0.7 GB) | global coverage | compact tier |
| **Whisper large-v3 turbo** (WhisperKit, ~1.6 GB) | 99 languages | word timestamps; wide-language fallback |
| **SenseVoice / GigaAM** (ONNX) | CJK/Cantonese/English, Russian | specialist coverage |
| **Transcription server** (`RemoteTranscriptionEngine`) | whatever the server's model covers | opt-in; OpenAI-style `/audio/transcriptions` (OpenAI, Groq, OpenRouter) or whisper.cpp `/inference` on another device. Packs VAD spans into clips (≤15 s, or ≤30 s for a diarized track), uploads 3 at a time, and attributes speakers word by word like Qwen3-ASR (`.alignedWords`). Servers in `wordTimingModels` (MAI-Transcribe-2, Gemini 3.5 Transcribe, and Whisper large-v3 turbo on OpenRouter) are asked for `verbose_json` with `timestamp_granularities[]=word`, and their word times replace the Qwen3 forced aligner, which is then neither downloaded nor run; an HTTP 400 to those fields falls back to `json` and the aligner for that origin and model until relaunch. Other servers use the aligner, falling back to speaker regions. Its origin needs its own audio approval (`approvedRemoteTranscriptionOrigins`); plain HTTP only on private networks and tailnets |
| **Cohere Transcribe** (2B) | 14 languages | legacy — hidden unless already installed (no language detection, timestamps, or diarization) |

For Ukrainian, choose **Whisper large-v3 turbo → Advanced → Language & vocabulary → Ukrainian**. The saved `uk` selection disables Whisper's automatic language detection. Multilingual Parakeet Ultra/v3 also accept `uk`, but FluidAudio's hint only constrains the Cyrillic script and cannot distinguish Ukrainian from Russian. Unsupported local models disable the option and reject a previously saved Ukrainian selection with an actionable error; switching models preserves the selection. A transcription server receives `language=uk`, with support determined by its model. Regression tests cover selection, settings upgrades and reloads, decoder options, request fields, and rejection before inference. Ukrainian audio accuracy still needs a real Ukrainian sample.

Models auto-download on first use (Hugging Face; the ONNX specialists fetch sherpa-onnx archives from GitHub) and are cached under Application Support. huggingface.co is blocked in mainland China, so Settings → Models → **Download models from** (`ModelDownloadSource`) can route pinned Hugging Face file downloads through HF-Mirror (hf-mirror.com, same paths) or ModelScope (modelscope.cn). `ModelDownloadRouting` rewrites only `huggingface.co/…/resolve/…` URLs at transport time; stored URLs, the Hugging Face API used by Browse Hugging Face, and GitHub archives are unchanged, so `ModelDownloadManager`'s pinning policy still applies. ModelScope tracks branches rather than Hugging Face revisions, so it is used only for files whose listed SHA-256 equals the pin; other files go to HF-Mirror, then Hugging Face. A mirror's file is accepted only after it matches the pinned size and SHA-256, otherwise the next source is tried, and callers verify it again as usual. ModelScope's `HEAD` returns no size, so its downloads use the single-stream path rather than ranged parts. The transcription language picker includes Serbian: Qwen3-ASR does not list it, but naming it explicitly lowered WER from 17.1% to 14.1% on 1.7B, where auto-detection reads it as Croatian ([Benchmarks/QwenSpanLength](../../Benchmarks/QwenSpanLength/results/2026-09-30/REPORT.md)).

- **Speaker attribution:** microphone speech is the user's (“Me”) while Settings → Summarization → Speaker names → **My microphone is me** is on (the default); the preference also normalizes old persisted track/diarization defaults when read. Turning it off, for shared-room microphones, keeps microphone voices unidentified until confirmed. Explicit corrections, voice profiles, overlapping speech, and suspected echo keep their own identity. Microphone text that mostly repeats simultaneous remote speech is treated as suspected echo for notes evidence: it is withheld from the model, cannot prove ownership, and cannot outvote the speaker's own identity. User confirmations and supported voice-profile evidence are separate from track origin. Cross-track loudness correlation marks possible echo without relying on identical ASR text; speech is retained unless the narrower waveform-and-text proof authorizes duplicate removal. Summaries and action ownership use the same normalized provenance. Calendar guests remain suggestions even when only one attendee is listed; attendance cannot identify a voice. A freeform alias “Me” becomes “You” only when its speaker identity is confirmed as the user.
- **Neural diarization:** Settings → Meetings → **Separate voices by speaker** partitions microphone and system audio before ASR. Fresh installs default to **Nemotron 3 (Preview)**, a post-recording model for up to eight speakers using FluidAudio 0.17.7's `offline` preset and the ANE-compatible v2 CoreML export. Existing selections are preserved; older saved settings without a model field keep Pyannote Community-1 (threshold 0.70, step ratio 0.15, min segment 0.3 s), which remains selectable. Overlapping voices remain unresolved. When turns cut the audio into regions, a region under one second that the engine rejects (Parakeet refuses audio under 0.3 s) is skipped instead of failing the track. Nemotron's approximately 200 MB CoreML download is pinned by revision and per-file SHA-256 under `Models/NemotronDiarization/` in app support. Preparation is coalesced across processing requests; model failures surface for retry instead of checkpointing generic-speaker success. Partial transcript keys include the backend/weight identity. See the [public AMI benchmark](../../Benchmarks/NemotronDiarization/results/2026-09-23/REPORT.md) and [integration notes](../../Benchmarks/NemotronDiarization/INTEGRATION.md).
- **Known-name vocabulary:** for prompt-capable engines (Whisper, Qwen3-ASR, Granite Speech 5.0), Settings → Models → Language & vocabulary → **Add names LokalBot already knows** (on by default) appends calendar attendee display names, speaker names applied in related meetings (same series or shared attendees), Dream projects the person pinned (unpinned model labels are left out, since they can echo earlier mishearings), projects tracked in Projects, and distinctive title terms after the manual vocabulary (`TranscriptionVocabulary`). Addresses and names derived from them, speaker evidence, and profiles are never read. Terms are saved per meeting in `transcription-vocabulary.json` so a crash resume reuses its track checkpoints; dictation uses recent attendee and pinned project names. A recording whose tracks contain no speech finishes with an empty transcript instead of failing, so it leaves the failed list and is not re-run at launch. Placeholder labels ("Them 6", "Speaker unclear") and the "· source 2" suffix meeting merges add to names are never fed to the recognizer, and department words in titles ("Product standup") are not terms. A prompt-capable model answers a near-silent span with the hint itself ("Mila Novak, Orion Launch, Acme." in 0.4 s); `TranscriptionPromptEcho` drops such rows in the Qwen engine and the track transcriber, and `TranscriptSanitizer` drops them again before notes, together with precisely timed rows of eight or more words at ten or more words per second.
- **Remote speaker names:** LokalBot does not read Google Meet participant names or speaking labels. Remote voices are named in the rename sheet from calendar guests and typed hints; attendance alone never names a voice. The retired Meet observer's leftover files are deleted by the hourly speaker-evidence cleanup, while names already applied to transcripts remain.
- **Audio clock:** the Core Audio callback copies only its host timestamp and validity with the existing pooled-buffer handoff. The writer records anchors after successful file writes, so microphone and system timing cannot bridge missing buffers, recovery padding, or invalid timestamps.
- **Review and meeting memory:** the rename sheet offers automatic provenance, ranked suggestions, supporting playback, dismissal, undo/reset, and resume. The encrypted identity journal is authoritative before public aliases are projected. Corrections win over stale results; retranscription remaps retained audio turns against an exact audio digest, including clean splits and rejection of conflicting merges. Existing summaries can be explicitly refreshed after a correction. Private evidence never enters `Transcript` or the CLI source graph.
- **Local voice profiles (always on):** processing always exposes Pyannote's `embedding256` chunk vectors, except for the sample meeting. With Nemotron selected, an additional Pyannote pass supplies compatible vectors, mapped to transcript speakers only by temporal coverage (95% for microphone chunks; 60% for call chunks, whose sentence pauses carry no other voice). Nemotron channel IDs and internal state never become identity embeddings. Existing profile fingerprints are retained after the runtime compatibility check described in the integration notes. Every name the user saves enrolls the voice when there is enough clean speech: at least three disjoint chunks totaling 15 seconds, which no other speaker overlaps. `MeetingSpeakerIdentityService.samePerson` adds it to the remembered person with that name when the voice agrees, else creates a distinct person. Microphone voices keep the per-chunk rules (one chunk per clean turn, every pair at least 0.75) and are only suggested. Call voices (`SpeakerVoiceMatcher.Call`) are codec-compressed, so single chunks disagree; up to 16 chunks are averaged into one voiceprint, a median chunk-to-average agreement below 0.75 marks a mixed label, and a profile keeps one average per meeting. A call voice is named automatically at 0.70 or more with a 0.15 lead over every remembered person with a different name, and suggested from 0.60. `SpeakerVoiceReplayTests` (opt-in, `LOKALBOT_SPEAKER_REPLAY_MANIFEST`) replays this on saved meetings; on seven real Google Meet standups, every automatic name agreed with the names saved there. Automatic names never train profiles. After launch and after each naming, `AppState.learnSpeakerVoices` analyzes the call track of meetings named before call voices were kept (once each, marked by `callVoicesAnalyzed`; only when the Pyannote model is installed, and never while recording or processing) and re-identifies meetings from the last 14 days with `nameAutomatically: false`: a saved transcript is never renamed in the background, because a new name invalidates its notes. Recognized voices become suggestions that the meeting offers through **Apply Names**. Profiles use bounded normalized vectors, exact model/preprocessing fingerprints, source contributions, revisions, and deletion tombstones. A profile database revision check rejects results computed before a rename, deletion, or enrollment change.
- **Storage and retention:** meeting-private AES-GCM identity journals live under `speaker-evidence/`; the same library root holds `speaker-profiles/profiles.sealed`. A serial store commits decisions, expires voice samples and suggestions independently of feature toggles, and preserves confirmed assignments. Source deletion revokes enrollments before deleting audio. Key/storage failures leave an advisory and never stop recording.
