# Email (read-only)

Part of the [development guide](../../DEVELOPMENT.md).

- **Accounts:** Settings → **Email** connects one or more Gmail accounts (`LokalBot/Services/Email/`), after a notice that says what is read. Sign-in uses LokalBot's own Google client, an "iOS"-type client with no secret (`GmailOAuth.builtInClientID`), in Apple's `ASWebAuthenticationSession` sheet, which returns only to the client's `com.googleusercontent.apps.<id>` scheme (`GoogleSignInSheet`). It uses PKCE and asks only for `gmail.readonly`. Under **Use your own Google OAuth client**, a person can import a Desktop-app client JSON (Keychain), which signs in through the browser and a `127.0.0.1` loopback redirect instead. Each account's tokens record the client that issued them, so refreshes use that client. `GmailAuthorizer` caches one Keychain token set per account and serializes refreshes; Disconnect deletes locally, then revokes. Nothing touches the Keychain until an account is connected. Google Cloud setup and verification: [Docs/guides/google-oauth-verification.md](../guides/google-oauth-verification.md).
- **What is read:** `EmailScope` decides from headers alone whether a thread is downloaded: the person wrote in it (Gmail's SENT label; a `From` header with their address proves nothing), or a calendar attendee from the last 90 or next 14 days takes part and the mail isn't bulk (Gmail's non-Primary tabs, `List-Unsubscribe`/`List-Id`, `Precedence`, `Auto-Submitted`, no-reply senders). Spam, Trash and Drafts are never kept, attachments keep only name, type and size, and messages older than 90 days age out. HTML bodies are tokenized to text without loading anything (`EmailText.plainText(fromHTML:)`); `<blockquote>` history keeps a `> ` prefix.
- **Sync:** `GmailSyncer` scans the window on the first pass (`in:sent` plus attendee searches), then replays Gmail's history from the saved `historyId`, rechecking only the threads it names (reading, starring and archiving are ignored), and searches once for any attendee added since; only searches that ran to the end mark people as searched. Attendees are remembered for 90 days after they were last on the calendar, so a calendar that is briefly unreadable deletes nothing and searches nothing. An expired history ID rescans the window. The cursor is saved only after the threads it covers are stored; a thread Gmail fails to return is kept as it was and retried next pass, while more than a few failures at once end the pass. Pruning drops a thread whose remaining messages no longer qualify. `GmailClient` sends only `GET` requests to `gmail.googleapis.com`, refreshes the token once after a 401, and backs off on 429, 5xx and per-user rate limits. `EmailController` checks each account once the library has loaded after launch, after 06:00 each day, 30 minutes before a meeting with attendees, every three hours, and on **Check Now**, never twice within 15 minutes; it doesn't run in headless commands or the UI test host. Tokens are read from the Keychain once per launch, and a Keychain read failure is reported, never treated as a sign-out. It refuses to save over an account list it couldn't read, and Disconnect removes the account, its mail and its tokens before asking Google to revoke.
- **Meeting briefs:** the only reader. `UpcomingMeetingPreparationModel` takes `EmailController.mailbox()` (reused until `mailRevision` or the event changes), and `EmailMeetingContext` picks up to five stored threads whose participants include the event's attendee addresses. Your own addresses are excluded, and display names never match. Threads are ranked by attendees involved, recency, an unanswered question to you, and subject overlap. Each becomes a "From email" row on the Today card, opening the thread in Gmail with `authuser`, plus a prompt block of the last three non-bulk messages tagged "you" or the sender. That text has quoted history and signatures stripped (`EmailText.conversationText`) and secrets redacted (`ScreenContextPrivacy.redact`), and it is capped at 3,000 characters. The brief's system prompt forbids following instructions in mail, and generation already refuses remote models. Earlier meetings now also match attendees by address.
- **Storage:** `email/accounts.json.enc` and `email/<account-id>/threads/<thread-id>.json.enc`, AES-GCM sealed with the `email-key` Keychain key, `0600` files in `0700` folders. Mail never enters `lokalbotv3.sqlite`, the embeddings, Dream reports or exports ([plan](../plans/email-access-plan-2026-10-26.md)).
