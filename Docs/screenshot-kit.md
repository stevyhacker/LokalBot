# Screenshot capture guide

`Scripts/capture-screenshots.sh` is the source of truth for README and product
screenshots. It builds the isolated **LokalBot UI Test Host**, seeds a synthetic
library, and renders the real SwiftUI window to Retina PNGs in-process. It does
not run the XCUITest suite, touch the installed app, require TCC grants, or use
personal meeting and screen data.

## Quick refresh

Requirements: Xcode, XcodeGen, CMake, and the repository's configured signing
team. A clean checkout builds or downloads the pinned native runtimes on its
first pass. From the repository root:

```bash
Scripts/capture-screenshots.sh --stills-only
```

The still pass writes eleven PNGs under `Assets/screenshots/`. Run the script
without `--stills-only` only when you intentionally want to rebuild the GIF
sequences too; that path also requires `ffmpeg`. Narrated website video is a
separate reviewed workflow described in `Docs/demo-film-kit.md`.

Don't click or type while a capture window is up. Input reaches the host, and
its Record button or ⌘⇧R records real microphone audio into the temporary
library (seen on October 9, 2026). After a run, search the library's
`debug.log` for `startRecording` and delete any `*-manual-recording` folder.

## Reproducible frame

- **Window:** 1400×880 pt, rendered at 2× (2800×1760 content plus title bar).
- **Meeting list:** capped at 400 pt so the outcome inspector remains readable.
- **Quick Recall:** 660×512 pt, title bar included, also at 2×. The website's Quick Recall images
  use `LOKALBOT_CAPTURE_SCALE=4`; above the display's 2× the host redraws text
  and shapes at the requested density, while icons and thumbnails keep their
  2× pixels.
- **Appearance:** light, pinned by the capture host rather than inherited from the
  current macOS appearance. Set `LOKALBOT_CAPTURE_APPEARANCE=dark` for a dark set.
- **Content:** English synthetic meetings, outcomes, work sessions, chats, and
  screen moments generated by `Scripts/seed_demo_library.py --profile studio`:
  a small video studio's calls and Apple apps. The frames show different
  examples: the podcast trailer review (meeting, studio list index 3),
  a "captions" search (Quick Recall), and a "MacBook" search (Ask search).
- **Replacement safety:** the full set is staged in a temporary directory. The
  committed images are replaced only after every PNG is complete and the
  summary/transcript duplicate-frame check passes.

You can experiment without editing the script:

```bash
LOKALBOT_CAPTURE_SIZE=1480x930 \
LOKALBOT_CAPTURE_CONTENT_MAX=420 \
Scripts/capture-screenshots.sh --stills-only
```

Keep the committed set at the defaults unless every README frame has been
reviewed together. Smaller windows can force three-column meeting layouts and
toolbars below their supported constraints.

The committed Autocomplete frame intentionally uses LokalBot's in-app preview,
which is deterministic and permission-free. A marketing shot of ghost text in a
third-party app must use the real Dev build with Accessibility and Input
Monitoring grants and should never replace this reproducible documentation
frame.

## Website set

The home page shows real recordings, not stills: `web/assets/demos/` holds every
clip and poster, in light and dark, filmed and cut by
`Video/lokalbot-landing-demos/` (see its README). The hero plays one film cut from
the hero clips by `full_demo.py`. Update the `aria-label`s and captions in
`web/index.html` when a clip's content changes. `autocomplete-ghost-<appearance>.webp`
are single frames of the `autocomplete` clip, 7.6 seconds in.

`web/assets/screens/` holds only:

| Files | Source |
| --- | --- |
| `linux-meetings.webp`, `linux-meetings-dark.webp`, `windows-today.webp`, `windows-today-dark.webp` | The Linux and Windows screenshots from the CI artifact of a `master` run, converted to WebP |
| `meetings-summary-light.png` | The `stills` take of `Video/lokalbot-landing-demos/film/film.sh`; the source for `web/assets/og-home.png` (`Assets/social-preview/og-home.html`) |

## Review before commit

1. Open every changed PNG at full resolution and at its README display width.
2. Check for clipped text, wrapped toolbar labels, stale terminology, personal
   data, and inconsistent appearance.
3. Verify dimensions with `sips -g pixelWidth -g pixelHeight`.
4. Update the nearby README caption and alt text whenever the UI meaning changed.
5. Stage only the intended docs and generated assets; keep video outputs and
   unrelated worktree files out unless they were explicitly part of the refresh.

`cacheDisplay` does not draw the sidebar's vibrancy selection material; it
comes out solid black. Scripted captures therefore draw the selected sidebar
row in AppKit's unemphasized selection color. Controls appear in their
inactive-window colors. Judge selection and accent styling in
a live window. Accent text contrast in both appearances is covered by
`BrandContrastTests`; rerun it after changing `Brand.teal` or a workspace
surface color.

The README opens with a looping recording of the real app, cut with the rest of its clips and
stills from the home page's demos; [their notes](../Assets/hero/README.md) cover those, and the
earlier composite hero from `Scripts/render_readme_hero.py`. It also uses
`autocomplete-memory.gif`, a loop cut from the autocomplete launch film's footage. [Capture notes](../Assets/screenshots/README.md) and
[the source manifest](../Assets/screenshots/readme.source.json) record the
release revision, date, dimensions, and hashes for the published set. Update
those records when replacing an image. The remaining stills support the
website, release notes, and future documentation updates.
