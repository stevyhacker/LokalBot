## What’s new

- **Faster library navigation and loading.** Indexed capture lookups, batched text reads, and background loading reduce work on the interface thread when opening days, screen moments, meeting documents, and conversations. Search shows lexical matches before semantic results, and repeated Markdown formatting uses a bounded cache.
- **More responsive Ask.** Supported chat backends can stream final-answer text with coalesced updates, while tool output and incomplete reasoning stay buffered.
- **Merge related meeting recordings.** Combine separate recordings into one meeting, undo a merge when needed, and keep deletion, recovery, and CLI visibility consistent. Meeting recaps and merged-meeting controls are more compact.
- **Better Agent responses and recording controls.** Agent responses render Markdown tables, approval mode is remembered, and manual recording remains available during calendar cooldowns. Browser meeting detection also receives reliability improvements.

## Performance measurements

| Measured operation | Before | After | Less time |
|---|---:|---:|---:|
| Fetch text for 40 captures | 297.37 ms | 0.17 ms | 99.94% |
| Single capture lookup | 7.75 ms | 0.018 ms | 99.77% |
| Load day context | 7.76 ms | 1.45 ms | 81.3% |
| Check day evidence timestamp | 9.62 ms | 2.32 ms | 75.9% |
| Reformat 20k-character Markdown | 16.59 ms | 0.028 ms | 99.83% |
| Semantic candidates, 6k synthetic rows | 1,548 ms | 1.89 ms | 99.88% |

These component benchmarks do not measure whole-app speed or end-to-end click latency. SQL comparisons use the same frozen library and the median of three runs. Markdown measures repeated formatting with a warm cache; the first parse is still required. Semantic candidates use synthetic data, with one baseline run and three after runs. See [PR #81](https://github.com/stevyhacker/lokalbot/pull/81) for methodology and validation.
