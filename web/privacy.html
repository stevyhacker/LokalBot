Privacy Policy

LokalBot is local-first. It has no LokalBot account, analytics service, advertising SDK, telemetry backend, or hosted AI service. This page describes the Mac app; Windows and Linux lists where the Windows and Linux app, an alpha, differs.

What stays on your computer

The project does not receive your recordings, transcripts, summaries, screenshots, prompts, files, email, calendar events, or usage history. LokalBot can store these in its Application Support directory:

  • meeting microphone and system-audio tracks;
  • transcripts, summaries, notes, search indexes, and meeting metadata, including attendee names and emails for calendar-matched meetings;
  • downloaded speech, embedding, and language models;
  • permission-gated app/window activity, screenshots, and locally extracted text;
  • records of local Claude Code and Codex sessions for the day digest (requests, commits, pull requests, and changed file names; never tool output or file contents), on by default and removable in Settings → Day Memory;
  • opt-in Agent Mode sessions and runtime files;
  • an encrypted Personal Context list of facts, preferences, goals, and principles about you;
  • conversations downloaded from email accounts you connect, encrypted (see Email from Gmail); and
  • preferences, diagnostic logs, and encryption keys.

Fresh installs select activity-only day tracking: the app name and window title. Visible text and encrypted screenshots are opt-in and require macOS Accessibility and Screen Recording permission. Screenshots are encrypted at rest and deleted after 14 days by default. Their extracted text follows the same retention unless you explicitly keep it. Overnight reviews, the one-line week and month summaries made from them for agents, and the remembered projects and goals are kept after screen text expires; Settings → Overnight review → Clear work memory deletes them. Dictation scratch audio is deleted after transcription by default. Dictated text is kept only as the last 10 results for 7 days, encrypted, so you can copy one again, and briefly for Learn from my dictation (below) while it is on.

Personal Context

Personal Context holds what you tell LokalBot about yourself: messages that start with “Remember …” in Ask, and items you add in Settings → Personal Context. With Learn about me from my meetings and work, which is on by default, LokalBot also learns from your own words after each overnight review. It reads your microphone lines from that day's meetings, the requests you typed to Claude Code or Codex, and your Ask questions. Only lines with first-person words such as “I” or “my” go to your Think model, and other people's words never do. Up to three items a night come from this, and a day is read again only when your lines from it change. Facts and goals you said in meetings are saved; preferences and anything from your typing wait for your review; principles and values are never learned. Each learned item shows the line it came from.

Learn from my dictation is off by default. While it is on, LokalBot keeps the words you dictate into other apps, encrypted, until that night's learning reads them, and never more than two days. It keeps only the words you spoke, only when they were pasted into a field it could identify, and skips excluded apps and websites, private windows, and password fields. Items from dictation always wait for your review. Turning it off deletes what is kept.

Items are encrypted with the key that protects your Ask history. Ask adds the relevant ones to each question, so an approved remote Think server receives them with the question. An item is removed when the meeting, conversation, or agent session it came from is deleted, or when the line it quotes is corrected or attributed to someone else, unless you chose to keep it. You can edit or forget any item, or turn learning off, in Settings → Personal Context.

When LokalBot uses the network

  • Models: model metadata and files from Hugging Face or a publisher's download host. Selected first-use models can download automatically. If you choose HF-Mirror (hf-mirror.com) or ModelScope (modelscope.cn) in Settings, model files come from there instead, and every file is checked against the size and SHA-256 LokalBot pins.
  • Updates: the public GitHub Releases appcast and a signed update when you check or enable automatic checks.
  • Optional email: after you connect a Gmail account, LokalBot checks gmail.googleapis.com for new mail at launch, every three hours, each morning, and before meetings with attendees, using Google's read-only permission. Signing in uses Google's own page in a macOS sign-in sheet. To find conversations with people on your calendar, it searches your mailbox for their addresses; those searches go only to Google. See Email from Gmail.
  • Optional remote inference: an Ollama or OpenAI-compatible URL you configure. Loopback stays on your computer. A non-loopback origin must be explicitly approved before it receives meeting, workday, Personal Context, or agent context.
  • Optional Agent Mode: setup downloads its pinned runtime. Commands you approve can access files or the network with your user account's permissions.

Those services receive ordinary connection metadata such as IP address and request headers. LokalBot adds no advertising identifier and does not use those requests for tracking. A remote server's operator controls its own privacy terms.

Email from Gmail

This is LokalBot's disclosure for data it receives from Google APIs. LokalBot's use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy and the Google Workspace API User Data and Developer Policy, including the Limited Use requirements.

  • What LokalBot reads: with the read-only Gmail permission (gmail.readonly), your Gmail address and its verified "Send mail as" addresses, Gmail's record of what changed since the last check, the headers and labels of threads that match its searches, and the text of conversations that qualify: ones you wrote in, and ones where someone on your calendar in the last 90 or next 14 days takes part and the mail isn't bulk mail (Gmail's Promotions, Social, Updates, and Forums tabs, mailing lists, and automated senders). It never reads Spam, Trash, Drafts, or attachment contents, and it loads no images, tracking pixels, or links. Google refuses any change to your mail under this permission, so LokalBot can't send, delete, label, or mark mail as read.
  • How it is used: only for features you see in LokalBot on your Mac. Today that is the account list and its status in Settings; nothing else reads the downloaded mail yet. Before a feature such as a meeting brief uses your mail, this policy will describe it and LokalBot will ask you.
  • Where it is kept: only on your Mac, encrypted with AES-GCM using a key in your macOS Keychain, with the sign-in tokens in the Keychain too. LokalBot has no server, so nothing is uploaded.
  • Who receives it: no one. LokalBot doesn't transfer or sell Gmail data to the project, advertisers, data brokers, AI providers, or anyone else, doesn't use it for advertising or credit decisions, and doesn't let any person read it. It is never used to develop, improve, or train AI or machine-learning models, and text from your mail is not sent to remote AI models.
  • Retention and deletion: messages older than 90 days are deleted automatically, and mail you trash or delete is removed at the next check. Disconnect in Settings → Personal Context → Email deletes that account's mail and tokens at once and asks Google to revoke access; you can also remove it at myaccount.google.com/permissions.

Permissions and consent

Microphone and system-audio permissions enable recording. Calendar access helps detect and title meetings and provides local speaker-name suggestions. Attendee emails remain in meeting metadata, are deleted with the meeting, and are never added to transcripts, exports, or model prompts; once you connect email, they also choose which mail conversations LokalBot downloads. Accessibility enables browser-meeting detection, Cotyping, dictation insertion, and approved agent interaction. Screen Recording enables visual screen context when selected.

On a fresh install, LokalBot asks through a notification before it records a detected meeting. You can switch to automatic recording or turn auto-record off. You are responsible for informing participants and obtaining any consent required before recording other people.

External-agent access

The bundled CLI and MCP interface are read-only and refuse library access until you enable Agent Access under Settings → Privacy. Screen memory and Personal Context each need their own, separate permission there; turning on one never turns on another. With Allow external agents to read what I shared about myself on, agents can read only the Personal Context items you mark Share with agents, at most 12 at a time, never the rest. The start-of-session briefing (get_briefing, lokalbot-cli brief) follows the same grants: with all of them off it only lists which are off, and each part, such as your open action items, current projects and goals, recent coding-agent sessions, or the overnight-review timeline, appears only under the permissions that cover its sources. An enabled external tool runs as your user account, and a connected AI client may send what it reads under its own privacy terms, so connect only tools you trust.

Windows and Linux (alpha)

The Windows and Linux app follows this policy, with these differences:

  • Storage: the library is in %LOCALAPPDATA%\LokalBot on Windows and ~/.local/share/LokalBot on Linux. API keys, the ChatGPT sign-in, calendar links, and the screen-image key are kept in the system credential store (Windows Credential Manager, or the Secret Service on Linux).
  • Not collected there yet: Personal Context, email, coding-agent session records, spoken summaries, daily memory notes, and meeting note export are Mac only for now.
  • System audio comes from the whole output (WASAPI loopback, or a PulseAudio or PipeWire monitor), so anything else playing during a recording is recorded too. Meeting detection looks at which apps use the microphone and asks with a notification.
  • Screen context reads visible text through accessibility (UI Automation or AT-SPI) and otherwise uses on-device OCR, downloaded only when you ask for it. The same exclusions, redaction, encryption, and 14-day default retention apply.
  • Dictation audio stays in memory and is never written to disk. The text is pasted through the clipboard, and your previous clipboard comes back afterwards. The last 10 results are kept for 7 days, encrypted, so you can copy one again.
  • Calendar reads private iCal or CalDAV links you add, fetched from their own servers every five minutes while calendar use is on, and on Linux the calendars of Evolution Data Server. Events stay in memory.
  • Permissions: there are no macOS-style prompts. Windows uses its own microphone privacy setting, and Wayland desktops may ask through portals for screenshots and shortcuts.
  • Network: models from Hugging Face and GitHub, the llama.cpp runtime from GitHub, the OCR model from the ocrs project, Agent Mode's Bun (GitHub) and pi (npm), update checks against GitHub Releases, the servers and plans you approve, and your calendar links. Updates install only when you choose.
  • External agents: the meeting-library and screen-memory switches in Settings → Privacy & Data work as on a Mac. Agents can't change settings there, and personal context stays off.

The full details are in PRIVACY.md.

Deletion, security, and changes

You can delete meetings in the app or remove LokalBot's library folder (its Application Support directory on a Mac). No software can promise absolute security. Report vulnerabilities through the private process in the security policy. Material policy changes will update this date and appear in release notes.
