## Build workflows

Build with Xcode 26.4 or newer (Swift 6.3 and the Metal toolchain), as required by the pinned MLX package. The app deployment target remains macOS 15.

The Xcode project is generated from `project.yml`. Regenerate it after editing project configuration or adding/removing source files:

```bash
xcodegen generate
```

Use the **LokalBot Dev** scheme for local development. Build it with:

```bash
xcodebuild -project LokalBot.xcodeproj -scheme 'LokalBot Dev' -destination 'platform=macOS' build
```

The prod and Dev targets share sources, but have separate bundle identities (`me.dotenv.LokalBot` and `me.dotenv.LokalBot.dev`) and macOS permission grants. `LOKALBOT_DEV` disables Sparkle's launch path in every Dev configuration. The dedicated **LokalBot UI Test Host** also sets `LOKALBOT_UI_TEST_HOST` and removes the menu-bar extra for XCUITest. Unit tests use the **LokalBot** scheme; see [Testing](#testing).

Dev and UI Test Host also have separate Application Support roots and Keychain namespaces. Dev starts with its own library and downloaded models; it never imports the release library automatically. An embedded CLI resolves the enclosing app identity, including when invoked through a symlink. `LOKALBOT_STORAGE_ROOT` remains an explicit fixture/storage override.

A release-identity build run from Xcode build products (any path under `DerivedData/` or `Build/Products/`) uses `~/Library/Application Support/me.dotenv.LokalBot.local-build` and its own settings suite, and never runs the library migration, so it cannot write the installed app's library. Set `LOKALBOT_STORAGE_ROOT` to point it at another library deliberately. Only one GUI process may use a library at a time: it holds `.instance.lock` in the library root, and a second copy waits up to 10 seconds for a quitting holder, then activates the running copy and exits. Headless flags, unit tests, and UI tests do not take the lock.

App Sandbox is intentionally disabled because Core Audio process taps do not work in the sandbox. Distribution uses Developer ID signing and notarization. When the user requests reinstallation of the installed app, use `Scripts/reinstall-preserve-permissions.sh` to validate signing identity and update it in place.

The first build uses `Scripts/fetch-llama.sh` and `Scripts/fetch-sherpa.sh` to vendor native runtimes. Read their pins and the Swift package versions from the checked-in configuration rather than copying version numbers from prose. Preserve pins unless the requested work needs an update.

The `lokalbot-cli` target shares `LokalBot/CLISupport/` and selected model files by direct source inclusion. It is built before the app and embedded in `Contents/Helpers/`; it is not a shared framework. `project.yml` separately copies `.agents/skills/lokalbot-cli/SKILL.md` into `Contents/Resources/lokalbot-cli/`. Keep that skill self-contained unless its packaging is also updated. `Scripts/build-mcpb.sh` packages the helper for GUI MCP clients.

Unit tests are hosted inside the prod app binary and link `libllama` directly; `-bundle_loader` resolves host-defined symbols only. Generated `default.profraw` coverage files are gitignored and should not be committed. Signing keys and populated environment files must remain outside version control.

## Recording & meeting detection

- **Detection:** native meeting apps combine process audio signals with bounded start/stop policies. Browser automatic starts require supported Google Meet in-call controls across consecutive observations; calendar entries and arbitrary browser output never authorize a start. Once authorized, an unreadable document, missing/unsupported controls, or a missing browser host does not stop or trim capture. Only explicit leave/end evidence, continuously verified bound-call closure after grace, a verified call in another room, or user Stop ends that browser recording. Meet's post-call page counts as leave evidence by its Rejoin and Return to home screen actions, whatever its heading says. Closure checks inspect other browser windows so moving the tab does not itself end the call. The original call binding survives uncertainty; a replacement browser host must verify the same room before capture attaches. While the bound call is unverified, the detector also reads other rooms (only the active calendar event's room when it has one); a call there that passes the normal start gate ends the stale session without trimming it and starts its own. While the bound call still holds its window, the next calendar event on the same room link splits the recording, as it does for native apps; an event in another room means the call is running over. A manual Start joins the detector's session only while its call is verified, and never takes an unverified call's room. A persistent notice explains that recording continues and browser process audio can include other tabs. Call observation diagnostics stay separate from content boundaries. The live capture environment reads each running app's pid, bundle id, and name once per process (`RunningApplicationCache`) instead of through LaunchServices on every 2-second detector tick, and `AudioSourceMonitor` queries Core Audio's process list on a utility thread. When a calendar-backed call ends on its own, rejoining the same event records again right away; after the user presses Stop, automatic detection waits five minutes before recording that event again. The next calendar event in a continuing call is a new meeting and records automatically even after the user stopped the previous one.
- **Two synchronized tracks:** `mic.m4a` (AVAudioEngine) captures microphone input; `system.m4a` captures the selected application process through a Core Audio tap. Audio source is separate from speaker identity. The engine re-installs its tap on `AVAudioEngineConfigurationChange` (AirPods/USB switches no longer truncate the recording), drains the converter on stop (keeps trailing audio), recovers helper-process changes without ending the microphone track, and encodes AAC off the real-time IOProc thread. A microphone that cannot be rebuilt within its fast retries (about ten seconds) is retried every 30 seconds for the rest of the recording, like system audio, instead of staying silent.
- **Recording timeline:** new recordings use timing version 2 and one continuous origin for both tracks and preview files. Late attachment, recovered gaps, and sleep insert bounded silence, preserving playback/transcript alignment. Detector lifecycle IDs prevent an unrelated native meeting-end event from stopping a manual recording. Historical version-1 recordings retain their original interpretation; repairing them would require a coordinated audio, transcript, and speaker-evidence migration.
- **Recovery and health:** meeting-intent recording persists its requested app/room and keeps late attachment alive for the recording's lifetime (fast initial retries, then every 30 seconds). Verified detector events wake it immediately; microphone-only intent never acquires a system source. Generation checks reject delayed work after Stop. The one-second watchdog reports missing successful writes at a five-second threshold, treats flowing silence separately, and checks disk space every 15 seconds. Persistent warnings and the menu-bar indicator supplement the per-source status. A warning becomes a one-time notification only once it persists (`CaptureWarningNotifications`): missing audio after 15 s, lost call status after the detector's 120-second grace, disk and write failures at once; dropped buffers never notify. `recording-health.json` records state transitions, dropped buffers, attempts, last verified observation, and completion. Capture warnings remain visible beside completed transcripts and notes; fewer than five dropped buffers per source do not count as a capture issue. Both recorders hand tap buffers between the real-time thread and the writer queue through a lock-free ring (`RealtimeBufferRing`), so a buffer is dropped only when all of them are in use. Browser observation enables a browser's page accessibility once per process: `AXManualAccessibility` for Chromium, `AXEnhancedUserInterface` only for Firefox, nothing for Safari.
- **Independent audio persistence:** both recorders attempt PCM recovery independently of AAC writes. Each track has a growing 16 kHz mono CAF plus independently closed PCM checkpoints under `mic.live.recovery/` or `system.live.recovery/`. Checkpoints target two seconds at buffer boundaries, close and synchronize before a SHA-256/frame-offset manifest is atomically saved, and consume about 230 MB/hour per PCM copy per track. Recovery reconstructs contiguous verified audio, can read an unmanifested final chunk, and retains original chunks on any coverage uncertainty. It never replaces a longer verified reconstruction with a shorter one. Redundant copies are removed only after complete primary decoding and duration/coverage checks (100 ms encoder tolerance). Relaunch repairs existing media without authorizing new capture. This is tested process-crash recovery, not a power-loss durability guarantee.
- **Capture priority:** new post-meeting jobs wait while recording starts or runs; active work yields at track/model phase boundaries after saving completed work. Recording no longer prewarms inference models. An in-flight model call is not forcibly preempted. Optional live transcription retains its separate opt-in.
- **Finalization:** stopping preserves failed metadata/processing-queue writes for retry and surfaces the error. Quitting saves automatic processing intent durably for the next launch without starting inference; an unsaved finalization cancels quitting so the storage error can be resolved and Quit retried. Reconnecting a microphone rearms bounded recovery after its earlier attempts were exhausted.
- **Missing transcripts:** after launch recovery, finished recordings of at least 5 seconds with readable audio, no transcript, and no queued, parked, or running job are queued once with automatic processing settings. A merged meeting whose transcript has no segment in the span of a source of at least 30 seconds is re-transcribed once; `transcript-gap-repair.json` records the attempt.
- **UI:** the menu-bar item exposes record state, start/stop, recent meetings, and pause/resume. A live meeting opens with quick notes and an opt-in rolling transcript. A completed meeting opens as a workspace with synchronized playback, reviewable action items, decisions, summary, transcript evidence, export, and reprocessing controls.

## Transcription & speakers

Engines (Settings → Models; CoreML/MLX, in-process, Neural Engine/Metal):

| Engine | Coverage | Notes |
| --- | --- | --- |
| **IBM Granite Speech 4.1** | high-accuracy local ASR | optional |
| **Parakeet Ultra 0.6B** (CoreML, ~0.63 GB) | 25 European languages | fast multilingual option; separate from existing v2/v3 selections |
| **Parakeet TDT 0.6B v3** | 25 languages, up to ~190× realtime in local benchmarks | fastest local option |
| **Parakeet TDT 0.6B v2** | English only | slightly higher recall |

| **Whisper large-v3 turbo** (WhisperKit, ~1.6 GB) | 99 languages | word timestamps; wide-language fallback |
| **SenseVoice / GigaAM** (ONNX) | CJK/Cantonese/English, Russian | specialist coverage |
| **Cohere Transcribe** (2B) | 14 languages | legacy — hidden unless already installed (no language detection, timestamps, or diarization) |

Models auto-download on first use (Hugging Face; the ONNX specialists fetch sherpa-onnx archives from GitHub) and are cached under Application Support. The transcription language picker includes Serbian: Qwen3-ASR does not list it, but naming it explicitly lowered WER from 17.1% to 14.1% on 1.7B, where auto-detection reads it as Croatian ([Benchmarks/QwenSpanLength](Benchmarks/QwenSpanLength/results/2026-09-30/REPORT.md)).

- **Speaker attribution:** microphone speech is the user's (“Me”) while Settings → Summarization → Speaker names → **My microphone is me** is on (the default); the preference also normalizes old persisted track/diarization defaults when read. Turning it off, for shared-room microphones, keeps microphone voices unidentified until confirmed. Explicit corrections, voice profiles, overlapping speech, and suspected echo keep their own identity. Microphone text that mostly repeats simultaneous remote speech is treated as suspected echo for notes evidence: it is withheld from the model, cannot prove ownership, and cannot outvote the speaker's own identity. User confirmations and supported voice-profile evidence are separate from track origin. Cross-track loudness correlation marks possible echo without relying on identical ASR text; speech is retained unless the narrower waveform-and-text proof authorizes duplicate removal. Summaries and action ownership use the same normalized provenance. Calendar guests remain suggestions even when only one attendee is listed; attendance cannot identify a voice. A freeform alias “Me” becomes “You” only when its speaker identity is confirmed as the user.
- **Neural diarization:** Settings → Recording → **Separate voices by speaker** partitions microphone and system audio before ASR. Fresh installs default to **Nemotron 3 (Preview)**, a post-recording model for up to eight speakers using FluidAudio 0.17.5's `offline` preset and the ANE-compatible v2 CoreML export. Existing selections are preserved; older saved settings without a model field keep Pyannote Community-1 (threshold 0.70, step ratio 0.15, min segment 0.3 s), which remains selectable. Overlapping voices remain unresolved. When turns cut the audio into regions, a region under one second that the engine rejects (Parakeet refuses audio under 0.3 s) is skipped instead of failing the track. Nemotron's approximately 200 MB CoreML download is pinned by revision and per-file SHA-256 under `Models/NemotronDiarization/` in app support. Preparation is coalesced across processing requests; model failures surface for retry instead of checkpointing generic-speaker success. Partial transcript keys include the backend/weight identity. See the [public AMI benchmark](Benchmarks/NemotronDiarization/results/2026-09-23/REPORT.md) and [integration notes](Benchmarks/NemotronDiarization/INTEGRATION.md).
- **Known-name vocabulary:** for prompt-capable engines (Whisper, Qwen3-ASR), Settings → Models → Language & vocabulary → **Add names LokalBot already knows** (on by default) appends calendar attendee display names, speaker names applied in related meetings (same series or shared attendees), Dream projects the person pinned (unpinned model labels are left out, since they can echo earlier mishearings), and distinctive title terms after the manual vocabulary (`TranscriptionVocabulary`). Addresses and names derived from them, speaker evidence, and profiles are never read. Terms are saved per meeting in `transcription-vocabulary.json` so a crash resume reuses its track checkpoints; dictation uses recent attendee and pinned project names. A recording whose tracks contain no speech finishes with an empty transcript instead of failing, so it leaves the failed list and is not re-run at launch. Placeholder labels ("Them 6", "Speaker unclear") and the "· source 2" suffix meeting merges add to names are never fed to the recognizer, and department words in titles ("Product standup") are not terms. A prompt-capable model answers a near-silent span with the hint itself ("Mila Novak, Orion Launch, Acme." in 0.4 s); `TranscriptionPromptEcho` drops such rows in the Qwen engine and the track transcriber, and `TranscriptSanitizer` drops them again before notes, together with precisely timed rows of eight or more words at ten or more words per second.
- **Remote speaker names:** LokalBot does not read Google Meet participant names or speaking labels. Remote voices are named in the rename sheet from calendar guests and typed hints; attendance alone never names a voice. The retired Meet observer's leftover files are deleted by the hourly speaker-evidence cleanup, while names already applied to transcripts remain.
- **Audio clock:** the Core Audio callback copies only its host timestamp and validity with the existing pooled-buffer handoff. The writer records anchors after successful file writes, so microphone and system timing cannot bridge missing buffers, recovery padding, or invalid timestamps.
- **Review and meeting memory:** the rename sheet offers automatic provenance, ranked suggestions, supporting playback, dismissal, undo/reset, and resume. The encrypted identity journal is authoritative before public aliases are projected. Corrections win over stale results; retranscription remaps retained audio turns against an exact audio digest, including clean splits and rejection of conflicting merges. Existing summaries can be explicitly refreshed after a correction. Private evidence never enters `Transcript` or the CLI source graph.
- **Optional local voice profiles:** **Remember speakers on this Mac** separately exposes Pyannote's `embedding256` chunk vectors. With Nemotron selected, an additional Pyannote pass supplies compatible vectors, mapped to transcript speakers only by clean temporal coverage. Nemotron channel IDs and internal state never become identity embeddings. Existing profile fingerprints are retained after the runtime compatibility check described in the integration notes. Only microphone voices can be remembered or suggested; remote participants' voices never enroll, and remote profiles from earlier versions stay listed until forgotten but no longer match. Only explicit user confirmations can enroll at least three independent clean turns totaling 15 seconds. Profiles use bounded normalized vectors, exact model/preprocessing fingerprints, source contributions, revisions, and deletion tombstones. Unknown and confusable voices abstain; recognition thresholds require held-out calibration. A profile database revision check rejects results computed before a rename, deletion, or enrollment change.
- **Storage and retention:** meeting-private AES-GCM identity journals live under `speaker-evidence/`; the same library root holds `speaker-profiles/profiles.sealed`. A serial store commits decisions, expires voice samples and suggestions independently of feature toggles, and preserves confirmed assignments. Source deletion revokes enrollments before deleting audio. Key/storage failures leave an advisory and never stop recording.

## Summarization & notes

- **Meeting boundaries:** the meeting actions menu exposes a range in original audio seconds. Rebuilding transcribes only that range; raw tracks remain playable. Only a confirmed call end can suggest an automatic boundary; user-reviewed ranges remain authoritative, and legacy ranges are not expanded silently. Meetings with saved audio beyond their boundary expose a review action using the existing rebuild path. Crossing old transcript spans are excluded until retranscription establishes their words. Reviewing a boundary clears the meeting's semantic vectors for re-embedding without writing a deletion tombstone; launch clears tombstones left on live meetings by earlier versions so keyword and semantic search cover them again.
- **Summary recovery:** old source-less rejection checkpoints receive a fresh scan with accepted evidence retained. New invalid source IDs or stalled generation produce an explicit persisted provider failure; identical retries do not repeat requests. Changing the provider/model invalidates that checkpoint. Parts are planned beside a full output reservation; a continuation page's ledger and recovery text shrink that output (down to the structured-output minimum), then keep only the newest ledger records.

- **Backends** (Settings → Models): **Built-in** (included localhost llama.cpp runtime; choose/download a GGUF model) · **Apple Intelligence** (FoundationModels, macOS 26+, gated so the app still builds/launches on 15.0) · **Ollama** · **any OpenAI-compatible server** (LM Studio, vllm-mlx, …). Non-loopback endpoints require explicit origin approval before context is sent.
- **Output:** `summary.md` with TL;DR / Key points / Decisions / Action items / Open questions. Long meetings are extracted in parts with no separate combining pass; the TL;DR takes every part's first takeaway, then every part's second, so its first bullets span the whole meeting. `<think>` reasoning blocks are stripped.
- **Outcomes:** `MeetingNotesGenerator` projects decisions and action items into the local outcome index while `MeetingOutcomeStore` keeps user status changes separate from generated source material. The meeting workspace and Today can therefore mark, reassign, or open work in Agent Mode without rewriting the transcript. A correction to an action's owner, text, or due date re-renders the summary's action list and keeps the rest, whose lines are claims attributed to the speaker who said them. Older summaries without saved claims (`summary-claims.json`) can name the old owner in free prose, so an owner or text correction there still asks for a refresh. Action items list the user's work first: their own commitments and requests they answered in the next turn, then unclear-owner actions spoken on the microphone, then every other action by importance. Saved outcomes keep every validated action; views that show a short list cap only their own presentation.
- **Action ownership:** who owns a task is read from the voice that said it, not from the model's `owner` field or its quote (`ActionOwnership`, `SpokenUndertaking`). The cited row's speaker owns the task when that speaker's own words around the cited rows undertake it — "I'll", "I will", "I have to", "I need to", "I can", "let me", "I have some comments to resolve" — wherever they sit in the sentence ("the extraction PR is something I I have to update"), with repeated or stumbled words collapsed and a sentence followed across the rows the diarizer cut it into. A condition or hedge ("if approved, I'll…", "maybe I'll…") changes when, not whose. Ownership is refused only on a contradiction: a negation, a question (direct, or "I'm wondering if I should…"), reported speech ("I said I'll…"), work handed to someone else ("I'll need you to…"), or a remark about the conversation ("I'll be honest", "let me share my screen"). When the same speaker also hands out work in the same breath ("I'll write the notes and Dana will handle the rollout"), the task must read more like the speaker's own clause than the other person's, or it stays unclear; a passive ("that can be simplified") and an embedded question ("what do we need to change") name no rival. Two people undertaking something in the cited rows need the model's quote to choose. A bare acceptance ("I can do that", "I'll take it") in the next turn takes on what the row before asked. The model's quote only chooses among undertakings; the saved quote is always the sentence as transcribed. Languages the wording checks cannot read (`SummaryLanguage.isMostlyEnglish` samples the whole meeting, so a foreign-sounding opening cannot switch them off) fall back to the cited voice plus the model's claim. A claimed commitment with no undertaking in or around the cited rows, or only negated and questioned ones, is not a task; a stray "not" or "?" elsewhere in the row decides nothing. When no task cites a row whose wording reads like the user's own undertaking, notes ask the model once more about that row; a complete answer without a task is final. A task that merely repeats its cited words merges into the task written from them. `ActionOwnershipAuditTests` (opt-in, `LOKALBOT_OWNERSHIP_AUDIT=<folder of copied meeting folders>`) replays every saved action of a library copy through the current rules and reports what would change, with and without the model's claim.
- **Action threads:** membership uses canonical immutable source text and compatible source owners, never fuzzy similarity or editable corrections. Corrections retain membership; mixed completion remains visible. A meeting-level toggle writes only its own overlay; a multi-meeting toggle requires native confirmation and rejects stale thread snapshots. Ask includes all statuses by default and supports explicit active/open/deferred/done filters with per-source status for mixed threads.
- **Thread corrections:** each corrected field keeps its own revision time, so completing an older source cannot replace newer wording, ownership, or deadlines. Sources can be kept separate and allowed to match again without changing generated outcomes. Clustering indexes canonical text and owner within the 30-day window; bulk edits notify dependent products once.
- **Meeting context:** notes receive a source-labeled secondary block (`MeetingGenerationContext`) with the calendar title and invited names, titles of documents on screen during the call (`MeetingScreenContext.materialTitles`, never captured text), and, when Settings → Meetings → Calendar → **Use invitation agendas** is on (off by default), the invitation agenda sanitized by `CalendarAgenda` and saved as `calendarAgenda` in `meta.json`. The block instructs the model never to derive decisions, actions, owners, or claims from it. Summarization → the two **Give notes…** toggles control calendar and screen titles.
- **Due dates:** `ActionDueResolver` deterministically resolves ISO dates, weekdays, day/week/month/quarter ranges, relative offsets, and month-day phrases (English and common Serbian forms) against the meeting date, or the correction date for user edits. Ranges resolve to their last working day; unsupported phrases stay unresolved. Labels keep the phrase beside the date, and Today's Needs Attention orders overdue then due-within-a-week threads first (`ActionAttentionOrder`).
- **Completion hints:** `ActionCompletionDetector` searches retained screen text captured after an open action was last mentioned for two of its distinctive words plus a verb-appropriate completion phrase (message sent, merged, submitted, event created, approved). Matches show **Looks done?** with Mark Done, View, and Not Yet; status never changes without confirmation, and dismissed captures are remembered in user defaults. Settings → Day Memory → **Suggest actions that look done**.
- **Follow-ups:** the meeting actions menu, a person's page, and the Command Palette open a follow-up sheet that starts from `FollowUpDraft.seeded` and can be rewritten by the on-device Think model (`FollowUpDraftGenerator`) from the recap, decisions, open actions, open questions, and invited names. It is copied or saved with the meeting, never sent; remote Think is refused.
- **Templates & language:** pick a notes template (Meeting / Lecture / Study guide / Podcast / Free-form) and a summary language (auto-detected via `NLLanguageRecognizer`, with Simplified / Traditional / Cantonese handling). Prompt budgeting (`TokenCountEstimator`, `PromptContextSanitizer`, `PromptSectionBudget`) keeps prompts within the model's context.
- **Notes context allowance:** for an approved OpenRouter origin, `OpenRouterModelCatalog` reads the selected model's `/models/<id>/endpoints` list (model id only, no API key) and `MeetingSummaryGenerator.contextTokenLimit` uses the smallest `context_length` or `max_prompt_tokens` across its endpoints. A failed lookup reuses the last published window from preferences, then `verifiedOpenRouterContextTokens` for the models the nightly drift job records (GLM-5.3, GLM-5.3 Flash, Qwen3.8 Flash), then 16K, which unknown external servers always get. Other OpenAI-compatible servers are asked for the window by `ServerContextWindowCatalog`, at most daily, with the configured API key: the model list's `max_model_len` (vLLM), `context_window` (Groq), `context_length` (Together, DeepInfra, Fireworks) or `max_context_length` (Mistral), and, for servers on this Mac, llama-server's `/props` slot window or LM Studio's loaded window. A reported window wins, even below 16K, and the last answer is kept in preferences. Cerebras and OpenAI publish no window through their APIs, so `MeetingSummaryGenerator.documentedContextTokens` uses their documentation: Cerebras's free-tier windows (Qwen3.8 27B 64K, gpt-oss-120b 65K) and OpenAI's by family at the smallest variant (GPT-4.1 1M; GPT-5, GPT-4o, GPT-4 Turbo and the o-series 128K). Each provider's window then sets its part size, below. Ollama requests ask for that 16K window with `num_ctx`, since Ollama's own default is smaller and drops the start of longer prompts; zero-reasoning requests also send `think: false`, and a reply cut off by its output limit (`done_reason: length`) is reported as truncated. Without a native tokenizer, UTF-8 bytes remain the hard input bound. Parts target 6,000 estimated tokens (about 18 KB) below a 64K window, 16,000 from 64K, and 24,000 from 128K (`MeetingSummaryGenerator.notesPartTokens`), so a 20-minute meeting on Cerebras Qwen is two requests instead of four. The steps keep a window that drifts between lookups from re-planning a meeting. A larger part gets proportionally more output (up to 16,384 tokens) and more notes and actions per request, and the job budget counts it as that many standard parts. Each part's schema lists its source IDs as enums three times, so hosted servers also bound part size by their limit on schema enum values (`TextEngine.structuredOutputEnumLimit`): Cerebras rejects more than 500, OpenAI documents 1,000, and OpenRouter and other hosted servers get 500; servers on this Mac compile the schema to a grammar and have none. A 20-minute meeting is therefore one request on OpenAI and two on Cerebras or OpenRouter. Changing the parts planned for a meeting discards its incomplete notes checkpoint.
- **Notes recovery:** a part continues only from records it already accepted; a page cut off before any record, for example because reasoning used the whole output, is scanned again rather than asked to "continue" from an empty list. Two answers in a row with no new records stop the part so automatic runs do not cycle; **Summarize again** clears that stop and scans the part once more. On Automatic reasoning, a task tuned for no reasoning sends Off to a model that reasons by default and can switch it off (Cerebras Qwen, OpenAI GPT-5.2 and later); other models keep their server default.
- **Pipeline:** runs automatically when a recording stops (configurable); serial queue with per-meeting status in the UI, plus a Process menu for manual re-runs.

## Built-in LLM runtime — llama.cpp & model catalog

- `LlamaServer` copies the vendored `llama-server` out of Resources into Application Support on first run (never executes from inside the bundle), spawns it (`-ngl 99 --jinja`, port 17872), health-checks `/health`, restarts on model switch, and terminates on quit.
- **Inference broker:** the three shared llama-servers — main (17872), embeddings (17873), cotyping fallback (17874) — are lease-managed by `InferenceBroker`: consumers take per-request leases, a server with no active leases unloads after a short linger, and loaded models sit under a RAM residency budget with LRU eviction. Settings → Advanced shows a live **resource monitor** of what's loaded and which lease is pinning it. The MLX speech engines (Qwen3-ASR, its forced aligner, Granite Turbo) idle-unload after two minutes, call the package's own `unload()` where it has one, and return MLX's GPU buffer pool (`MLXMemoryRelease`), which otherwise stayed allocated (4.3 GB after one meeting).
- **Model catalog** (Settings → Models) — download / cancel / delete with progress, radio-select the active model. Qwen "thinking" is disabled for summaries via `chat_template_kwargs`. The Models tab also manages the dedicated cotyping model, the embedding model, and the **Kokoro** TTS voice (sherpa-onnx; downloads once, then reads summaries and chat answers aloud offline).

## Search & player

- **Index:** SQLite + FTS5 (`lokalbotv3.sqlite` — system SQLite, no dependency) over titles, transcript segments, summaries, the user's `notes.md`, current outcomes (decisions, actions with saved text/owner/due corrections, and open questions), and OCR'd screen text. Ask's result types include Notes and Outcomes; a one-time `search-notes-outcomes-v1` migration reindexes older libraries, and note or outcome edits enqueue a reindex. Notes are also embedded for search by meaning. Segment rows carry their audio timestamp; incremental re-index by file mtime on launch and after each pipeline run.
- **Semantic search:** transcript/summary chunks and retained screen OCR are embedded with EmbeddingGemma 2 GGUF (`Q8_0`, approximately 0.31 GB, 768-dimensional vectors) on a second llama-server instance (port 17873, `--embeddings -b 2048 -ub 2048`). The GGUF carries the model's mean pooling and projection, so the server sets no pooling flag; as a bidirectional encoder it needs each input in one micro-batch, hence the 2,048-token batch. Queries use the checkpoint's `task: search result | query: ` prompt and documents `title: none | text: `, with prompt caching off. Vectors live in SQLite with an index-version marker covering the model, pooling, prompts, and chunking. Queries use brute-force cosine similarity. Screen results fuse FTS and semantic ranks with deterministic reciprocal-rank fusion while preserving the exact snapshot id. EmbeddingGemma 2's image encoder remains future work for direct image-vector retrieval; see [Benchmarks/EmbeddingGemma2](Benchmarks/EmbeddingGemma2/2026-10-07/REPORT.md).
- **UI:** sidebar Today | Meetings | Timeline | People | Projects | Ask | Agent | Settings. Ask searches as you type and keeps the conversation column in place. One date control offers Any time, Today, Yesterday, Last 7 days, and a specific date across meeting, activity, and screen search and answers. Selected result-type and screen-app filters appear as removable labels beside the query; empty results offer Clear search filters. Source and result-type choices remain in the source menu. Civil-date ranges persist with questions and survive reopening and retries without widening retrieval. Keyword and available semantic rankings blend automatically, respecting the semantic-indexing preference. Reading excerpts remove generated metadata and malformed repetition; semantic meeting hits recover the original indexed passage instead of displaying an old truncated embedding prefix. Keyword matches appear first and semantic suggestions are labeled **Related by meaning**. **Answer sources** lists the meeting/date and screen-moment boundary before sending, including collapsed matches and attached screens. For keyword input, Return opens the selected result with playback paused and never starts inference; question-like input (`AskIntent`) makes Return ask instead, unless a result was picked with the arrow keys. **Command-Return** or **Ask about results** always submits a question bounded to the displayed meetings and screen moments, through the same path as a Return-submitted question. A selected Activity source stays available, since activity has no result rows to bound. With no results, Ask uses the chosen source/date scope; result-type and screen-app filters constrain search results only.
- **On screen during a meeting:** captures stamped with the meeting id (plus unstamped legacy captures inside the call) become `MeetingScreenContext`: the Summary tab lists documents, pages, and windows that appeared (excluding the call itself), each able to play from its first appearance or open the retained capture, and the Transcript tab shows the window on screen at the playhead. Titles, document names, and URLs only; retention applies.
- **Player:** mic + system tracks play in sync (shared device-time anchor); seek bar; click any transcript line to jump the audio there; the currently-playing segment is highlighted.
- **Meeting summary:** a single Summary tab shows a bulleted recap (whole points expand after five), editable actions, decisions, and open questions, with full notes behind **Show full notes**. Find-in-page opens the full notes automatically when needed. Processing badges remain on library rows; failures expose a conditional retry banner. A single Summary notice links to speaker review, where action-linked speakers appear first and substantive voice excerpts replace filler-only samples.
- **Meeting review:** the Review tab connects bounded speaker excerpts (at most 12 seconds), existing speaker confirmation, action-owner corrections, and an explicit refresh of derived notes. When a speaker change archives the old extraction, Review retains those actions with a stale notice so owners can still be corrected; archived actions stay out of the current action index until refresh. Refresh shows the selected inference destination; saved action corrections remain separate from regenerated extraction. Mixed or unresolved voices are never silently named.

## Ask assistant — conversational Q&A over your library

- **Chat with your meetings:** pressing ⌘↵ in the **Ask** section escalates your query to a conversational assistant over your library — ask what was decided, find action items, or search transcripts in natural language. A small ReAct agent (`ChatAgent`) reuses the selected `TextEngine` and calls tools to ground every answer. With the built-in default it stays on the Mac; an approved remote backend receives the prompt context needed to answer.
- **Tools (pi-agent style, mirroring the CLI):** `search_meetings` (FTS5 keyword + optional semantic search), `list_meetings` (filter by title), and `get_meeting` (read a meeting's summary, or its transcript one 6,000-character window at a time; a cut window names the timestamp to continue from with `from=HH:MM:SS`). The agent picks a tool, reads the observation, then answers — citing meeting titles and dates, and saying so plainly when nothing matches.
- **Limits:** the system prompt ends with the current local time so relative dates resolve. Each turn replays up to 16 recent messages within 12,000 characters, never starting with an answer whose question was cut, and allows six tool calls before a forced answer that must say what it could not check. Apple Intelligence keeps four tool calls and eight messages within 4,000 characters for its small window.
- **Robust protocol:** tools are advertised in the system prompt with the recent-meeting list as ambient context; a tool call is parsed from a JSON object **or** a model's native `name(arg=…)` function-call form (smaller Qwen models emit the latter), with a tolerant fallback to a plain answer so a sloppy reply never hard-fails.
- **Reuses the configured backend:** built-in llama-server by default, or Ollama / OpenAI-compatible / Apple Intelligence — the same Settings → Models choice.

## Day tracking — Today, Timeline, and Ask

- **Default modes:** fresh settings select activity-only day tracking. Accessible text and encrypted visual context require opt-in and applicable macOS grants. Settings → Recording → Day tracking can also turn collection fully off.
- **Sampler:** frontmost app + focused-window title every 5 s, idle-aware (3 min), minimum 5 s block, pause/resume from the menu bar. A metadata-only Accessibility read checks secure fields and excluded apps/domains without reading document text; browsers, web-based apps, and private windows are tracked by name and title. Only excluded apps and excluded sites become anonymous “Private” duration blocks; other samples keep the app name, and the title unless a secure field is focused or a site exclusion cannot be ruled out. Stored in `activity_blocks` (same SQLite db).
- **Timeline sessions:** titles use duration-ranked observed window/document titles, with the original app/time blocks available for inspection. Sessions split at gaps over five minutes, a sustained new document after ten minutes, or the next source boundary after 45 minutes. Individual and overlapping blocks stay intact; brief app interruptions do not force a new session. These labels describe captured evidence, not inferred tasks.
- **Today:** the default landing page combines capture state, the current day digest, open meeting actions, upcoming-meeting preparation, and direct routes to Ask, Timeline, and Agent Mode. The reading column puts decisions and next steps before the current work summary. The shared digest keeps freshness in a compact footer and the expandable Yesterday recap below current work; previous-day provenance is inside that disclosure. Calendar setup lives in Settings. The next meeting leads with Join/Record, and the rest of today's meetings follow in a compact Later today list. Events with other attendees or a conferencing link are meetings; a solo event is listed without Join/Record when its title names a meeting (for example “Product Standup”), and personal appointments are left out.
- **Timeline:** groups adjacent activity into meaningful work sessions and interleaves meetings chronologically. A resizable Work sessions rail on the right leaves most width for the full day digest, open actions, and Day Overview at the bottom. Selecting a session, meeting, activity, or moment replaces the digest column with its details until Back returns to the day; narrow windows stack the digest, sessions, and overview in one column and open details in a drawer. Selecting a session foregrounds its captured text or encrypted visuals, with full window titles expandable and secondary session statistics disclosed below; **Browse raw capture** retains the per-block track for exact evidence and a reviewed time-range deletion of screen captures.
- **People:** `PeopleDirectory` joins calendar attendee names, speaker names the user applied (and their calendar-identity links), and action owners into one person per attendee address (used only as a private join key, never shown or exported), or per full name. An attendee without a display name takes the rename picker's address-derived name, except single-word mailboxes on public providers, which are usually handles. A lone first name joins the one person whose full name starts with it. Speaker labels, group or role owners ("Engineering team", "Product/research"), merge suffixes, and the Mac account's name are never people. Each person lists what the user owes them (open actions naming them or from meetings with at most two other people), what they owe the user, decisions from meetings of at most four people, and shared meetings. Actions can be filtered by person. `WorkMemoryConnections` rebuilds People and Projects off the main actor, reading transcripts for applied names only from the last 180 days, cached by file date.
- **Projects:** `ProjectLinks` joins each active Dream project to recent meetings whose title or summary contains every significant word of its name, open action threads from those meetings or naming it, decisions naming it, people from those meetings, and the last seven days of window time whose titles name it. Pinning uses the existing Dream memory pin. `ProjectTopicDetector` adds recurring topics: proper nouns that are nearly always capitalized and appear in at least three of the last 120 days of meeting titles, summaries, actions, and decisions, excluding people's names and short forms, app names, and generic work vocabulary. Each meeting row shows the summary line that mentions the project.
- **Morning brief actions:** Dream action candidates carry `[A1]`-style handles; the model is asked to begin a top action with its handle, and `DreamPrompts.linkTopActions` maps handles to thread ids (`DreamReport.topActionThreadIDs`), so linked actions render as checkable threads. The evidence-only fallback links its ranked threads too.
- **Day digest:** "Write digest" / "Update digest" runs the configured LLM over the day's blocks, meetings, and captured text → `journal/YYYY-MM-DD.md`. The same digest is visible from Today and Timeline, can be copied or exported, and grounds **Ask about day**. Each evidence segment is extracted separately: substantive work leads the task list, and lighter but identifiable work follows it instead of being dropped. A segment, about an hour of continuous activity, returns its main work item plus up to two other distinct items (`other_tasks`), so an hour that interleaves a fix, a review, and an email need not pack them into one line. On the synthetic benchmark in `Benchmarks/DayDigest/` this raised items with their own task line from 34% to 62% with Qwen3.5 4B. Work done through an AI assistant or coding agent counts as substantive when the evidence names a concrete task. External Think servers share one request gate per origin (`RemoteInferenceGate`): processing runs at most two requests at once, scheduled work (digest, Dream, briefs) on at most one of them, meeting notes at `pipeline` priority ahead of it, chat, dictation, and agents never queue behind processing, and a 429 pauses the whole origin for `Retry-After` or an exponential cooldown (2–60 s). The gated engine retries transient errors (429, 5xx, dropped connection) up to five attempts for notes, four for scheduled work, and two for chat, so callers do not replay on top. Segments are sized by active time: one per hour of a session (never more than it has events), at most 16 a day, instead of a fixed eight. Answers to unchanged segment and aggregation prompts are reused from an in-memory `DayDigestSegmentCache`, purged for a day whenever its evidence is deleted or corrected. After an evidence change the scheduler waits 20 s for notes, outcomes, and indexing to settle, and keeps a failure's 15-minute backoff.
- **Coding agent sessions:** on by default (Settings → Day Memory). While enabled, `CodingAgentEvidenceIngestor` reads Claude Code and Codex transcripts (`LokalBot/Services/CodingAgents/`) for the digest's seven-day window every ten minutes and before each digest run. It splits sessions into bursts at ten-minute idle gaps and stores only settled bursts in `coding_agent_bursts`, so a digest's inputs cannot change while it is written. Removing or correcting a stored burst, for example after a folder exclusion or a deleted session, goes through `withPrimaryEvidenceChange` as a revision; only **Delete saved agent sessions** withdraws the generated journal. An unreadable transcript never counts as a deletion. Bursts follow screen-text retention. The journal lists them under `## Agent sessions`, using recorded facts only: requests, actions, PRs, and changed files. The model reads each burst as `WORK SOURCE: AGENT SESSION` evidence. A segment merges a session's bursts into one detail and reserves up to six of its twelve detail slots for sessions, those with recorded outcomes first. While a session covers the time, screen text from agent host apps (Claude, Codex, terminals, editors) keeps one sample. Segment extraction yields one task per segment, which would drop parallel sessions. So each session that recorded an outcome (except scheduled runs) also becomes a task stated from its actions. These tasks are added after aggregation, merging into a model task only when the titles match. Scheduled runs' reports are withheld from the model because they often describe other days. Bursts also fill the fallback task list. Days without bursts keep their previous evidence signatures.
- **Scheduled digest and Dream:** automatic digests preview today after the configured hour and finalize every missed day of the last seven, oldest first, once its journal predates that day's end; days without evidence are skipped. Overnight review catches up the same seven-day window after its hour once LokalBot is not recording or processing and the Mac is on AC power. Both use the Think connection's origin approval; there is no separate scheduled-run approval.
- **Background work card:** `BackgroundActivityMonitor` combines published state from the processing pipeline, day digest runs (segment progress), the Dream scheduler, model downloads, and the semantic backfill into the sticky sidebar card above the storage summary. It shows the highest-priority activity, lists the rest in a popover, and routes each row to its meeting, day, Today, or Models settings.
- **Digest provenance:** version-2 metadata fingerprints the exact digest inputs and generated journal bytes. Dream, exports, and routines reuse a digest only while both match, including after corrections or deletion of the last source. Legacy unsigned journals remain readable but are not reused as verified evidence until regenerated. Automatic repair preserves edited signed journals; explicit meeting/screen deletions invalidate dependent day products. Only those deletions (`AppState.EvidenceChange.removal`) withdraw a generated journal. Reprocessing, transcript and outcome edits, saved moments, and re-read agent sessions are revisions: the journal stays, shown as out of date, until the scheduler or the person regenerates it. Before 2026-10-07 every revision deleted it, so a summary rerun right after a manual digest made the digest vanish. Days older than the retention window are never shown as out of date for a fingerprint mismatch alone, because expiry, not new work, explains it.
- **Refresh ordering:** generation rechecks the journal revision before saving, preserving edits made while the model runs. Persisting a digest reopens exports and routines that may have finished earlier. Meeting edits invalidate every Dream report whose 14-day comparison window includes the source. Screen, activity, coding-agent, and past-day digest changes are activity-only: they revoke the reports and memory that read that day's screens or digest and leave meeting-derived facts alone; today's digest refreshes revoke nothing. Scheduled retention is not such a change: expiring screen text, titles, and agent sessions (`AppState.withScheduledRetention`) leave that day's generated journal, Dream reports, and work memory, which outlive the screen window. The journal is not reconsidered either, so it is never rebuilt from what retention left. Settings → Overnight review → **Clear work memory** deletes all of them; a dream that started before the clear cannot write back (`DreamStore.clearAll`). An in-flight generation is checked against its own sources when it commits, so an unrelated change no longer discards it. Dream's 24,000-character evidence gives the day's journal at most 12,000: its summary, meetings, agent sessions, and time allocation first, then as much of the raw activity log as fits, so app totals, saved moments, the comparison window, and action handles always arrive. Dream requests cap output at 4,096 tokens and reasoning at 1,024; an automatic run that hits a rate limit or dropped connection is retried after the 15-minute backoff, and only the third consecutive failure for a day writes the evidence-only brief. The retention pass records its last run in the library (`.screen-retention-last-pass`), so relaunching does not repeat it.
- **Dream retraction:** app-owned provenance follows facts across memory merges. Source deletion/correction retracts dependent projects, goals, patterns, and reports, including pins; unattributed legacy facts are conservatively removed on evidence mutation. Stable meeting IDs and conservative civil-date coverage handle timezone changes. A root-level revocation intent and process-shared lock protect source writes and prevent stale in-flight commits or restart recovery from reviving withdrawn facts. Automatic screen retention uses the same boundary and deletes only reviewed rows.

## Autocomplete (Cotyping engine)

- **Ghost text everywhere:** as you type in almost any macOS text field, a gray suggestion appears next to the cursor; press **Tab** to accept the next word or phrase (Settings → Writing → **Each accept takes**), **`** to accept the rest, keep typing, or press **Esc** to dismiss. The subsystem remains named Cotyping in source and settings keys. Its Accessibility poll resolves the focused field and caret, a `CGEventTap` watches keystrokes, a borderless click-through `NSPanel` renders at the caret, and accepted text is inserted as synthetic Unicode keystrokes.
- **Flow while accepting:** a suggestion starts at up to four words (Settings → Writing → **Suggestion length**). While it is accepted or typed through, `CotypingSuggestionExtension` tops it up once two words are left, so the ghost stays a few words ahead until the sentence ends; words already shown never change, and a sentence that ended is not continued. Tab takes a word without its trailing punctuation unless **Accept punctuation with the word** is on. Escape on a visible suggestion dismisses it without reaching the app and holds that field for ten seconds (**Escape on a suggestion** can send the key through; a composing input method always receives it). Search fields stay quiet. These follow a live comparison with Cotypist recorded in [Docs/CotypingParityQA.md](Docs/CotypingParityQA.md).
- **Fields that report no caret:** some fields, such as Chrome's text areas, answer every caret query with an empty box. With Screen Recording already granted, `CotypingVisualCaret` captures the field's frame (scaled to twice its point size), finds the line that ends at the caret with Vision's fast text recognition, and keeps only the caret's position; typing along that line moves it by text width without another capture. Without it, or in excluded apps and sites, the suggestion is shown as a popup just outside the field, never over its text.
- **Its own dedicated on-device model:** Autocomplete decodes a dedicated model (recommended **Gemma 4 E2B Base**) **in-process via libllama** for low latency, with the localhost `llama-server` as the fallback. The prompt treats the model as a pure text continuer; a shared normalizer strips chat/`<think>` scaffolding, prompt echoes, and trailing-text duplication, then collapses the result to one line.
- **Completion quality:** **Gemma 4 E2B Base (Autocomplete)** is the first-launch default and the Balanced local preset's autocomplete model (3.85 GB, intended for 16 GB+ Macs). Existing saved selections are preserved. **LFM2.5 1.2B Instruct** remains available in the Lightweight local preset. Prompts retain paragraphs, lists and caret whitespace, keep up to 500 words within the existing 2,500-character window, and use concise subject/topic context. Native decoding enforces a typed space and ranks compatible tokens for rare word fragments; actual token counts bound the context window. Base completion models are excluded from the Main LLM picker.
- **Visible reply context:** the **Use visible text above the field** setting (on for new installs; saved settings without the key decode as off, so earlier installs keep theirs) captures up to three visible Accessibility messages/labels (420 characters) in the focused input's column, within 600 points above it. A bounded 70 ms/180-node traversal selects geometry before text; no pixels, OCR or whole document values are read. Shared capture exclusions, autocomplete exclusions, browser-origin checks and private-window titles (`ScreenContextPrivacy.isPrivateWindow`) apply before reading content. Context is revalidated before display and while active; Tab requires a validation no older than 600 ms and never traverses the screen. Unsupported or timed-out reads fall back to ordinary completion. Context-grounded text does not enter local learning. The native model [visible-context replay](Benchmarks/Cotyping/README.md#visible-context-and-memory-replay) uses the same traversal on synthetic AX trees.
- **Relevant saved facts:** two independent, default-off settings allow meeting/work memory and screen-derived work memory. A local lookup selects at most two 180-character snippets, limited to the last 90 days, from current meeting notes, summaries, corrected outcomes, and attributed Dream projects/goals. The two grants are the whole permission to read saved work memory: they apply whether or not Overnight review is scheduled and never start a review; mixed provenance requires both source grants. FTS finds meeting candidates but never supplies prompt text. A fact qualifies only when its source is named (at least half of the title's distinctive words appear in the draft, window title, or selected visible text) or when it shares two distinctive words with the user's own draft or window title, one written as a name, or three when none is. Everyday wording, calendar words and app names (`CotypingMemoryContext.everydayTerms`) never count, a notes line that adds no word to its source's title (a heading) is dropped, and writing with no distinctive word returns before any file is opened. Visible text can name a source but never counts as the user's own wording. Settings shows each grant's effective state (available, unavailable and why, or nothing saved) and whether the last lookup found anything. Source edits/deletion or permission changes invalidate affected requests and cached suggestions; accepted memory-grounded suggestions are excluded from the learning store. Setup samples never retrieve private context. See the synthetic [memory replay](Benchmarks/Cotyping/README.md#saved-memory-replay), which scores ignoring irrelevant memory alongside recall.
- **Opt-in & private:** off by default; needs **Accessibility** + **Input Monitoring**. Never reads password/secure fields; honors a per-user app exclusion list (preseeded with password managers and terminals).
- **In-app preview:** Settings → Writing exposes readiness and a rehearsal that runs the real prompt, model and normalizer before the feature is enabled system-wide. The rehearsal and the live accept tap share `CotypingContinuationAcceptance`, so a rehearsed Tab takes the configured word or phrase with the same spacing and punctuation, the full-accept key takes the rest, typing the suggested characters walks through the ghost, and moving the caret or typing anything else discards it. A synthetic sample conversation above the reply field stands in for nearby text when that grant is on (it goes through the same bounded selection; the screen is never read), and each optional source is listed as used, found nothing relevant, off, or unavailable. The menu bar provides the quick toggle.
- **Typing measurements:** generation latency alone leaves out the wait for the host to publish a keystroke, the pause before suggesting, context lookup, validation and the overlay. `CotypingLiveMeasure` records, per kind of app, the time from the last keystroke to a visible suggestion, whether an accepted suggestion then appeared in the field (`CotypingInsertionCheck` compares the published text with what was sent), and whether it was deleted or undone at once. Only the whole inserted text counts as arrived, and a check closes on its own after 1.5 s, so an app that ignores an insertion is counted and the compared text is not kept. Counts and timings only. Settings → Writing → **Usage and timing** shows, copies and resets them; `--cotyping-measurements` prints them for scripts.

## Dictation — system-wide voice typing

- **Hold ⌥ Space and talk** (or switch to toggle mode, or record another shortcut in Settings → Dictation: a key with ⌃, ⌥ or ⌘, a function key, or two or more modifiers alone such as ⌃⌥; the global shortcut pauses while you record. A modifier-only shortcut is observed, not consumed: push to talk starts after a 0.2 s hold, toggle fires on a clean release, and any other key pressed during the chord means it was another shortcut): a floating pill shows recording state and a live transcript while you speak; release, and the text is pasted into the focused app — or copied to the clipboard instead (Settings → Dictation).
- **Your ASR, prewarmed:** dictation reuses the transcription engine and language you picked under Models (Granite, Parakeet, Whisper, Qwen3-ASR, …) and prewarms it when the shortcut is armed, so short dictations start instantly.
- **Considerate capture:** playing media (Spotify, Music, browsers, VLC, …) is paused before recording starts; browser pausing skips live streams and supported conference domains. Audio goes to a local 16 kHz PCM scratch file and is deleted right after transcription.
- **Headset-safe microphone:** dictation records through an `AVCaptureSession` (`CaptureSessionMicrophoneInput`) opened off the main thread, not the meeting recorder's `AVAudioEngine`. The engine stops on every hardware format change, and AirPods change format when their microphone opens, so the engine stopped, released the microphone, and restarted in a loop that kept only fragments. More than three microphone recoveries within 20 seconds end the dictation with what was captured and an error naming the cause. The HUD waveform moves only while audio arrives, and the compact HUD shows "Reconnecting microphone" or "Waiting for the microphone" in its place. Recovery events are written to `debug.log`.
- **Recording feedback:** the HUD bars follow measured microphone loudness (`AudioLevelMeter`), and the recording dot stays grey until the microphone delivers its first audio, when an optional sound plays. Esc cancels a dictation that is starting or recording. Trigger modes are Push to talk, Toggle, and Tap or hold (a tap under 0.3 s keeps recording until the next tap; a longer hold finishes on release). Settings → Dictation → Microphone chooses the input (`DictationMicrophone`); with AirPods, the MacBook microphone keeps the headset in high-quality audio. When another app has Secure Input on, the Dictation page and menu bar say the shortcut is hidden from LokalBot.
- **Paste delivery:** the text is pasted where dictation began. Text selected before dictating is replaced; a selection that changed, a different field, a password field, or a field Accessibility could not read copies the text to the clipboard with a message naming the reason. The dictated text is promised to the pasteboard and marked transient, so the old clipboard is restored only after the app reads it; if no app reads it within 1.5 seconds, the text stays on the clipboard. A password manager's concealed item is not put back. After the paste, the bounded text before the caret in the same field is read back for about a second (`DictationInsertionCheck`, comparing the last words); if a readable field lacks the text, the overlay offers to copy it. The shortcut never cancels a dictation that is being transcribed; while the speech model needs attention it retries instead. Optional Compose context requires an unchanged focused window and field and honors the shared app/domain/private-window policy and credential redaction. Compose requests never open a thinking turn (zero reasoning budget, temperature 0.2, at most 4,096 output tokens), so the rewrite is not delayed by reasoning.
- **Grounded Compose:** separate, default-off grants allow visible text above the field, meeting/work memory, and screen-derived work memory. Explicit writing requests such as “reply” or “draft” can combine the current conversation with up to two relevant saved facts; source titles must match the request or authorized screen context. Nearby text uses the shared 420-character Accessibility selection with a single background worker and a 150 ms deadline. Directly dictated sentences get cleanup without these sources, sent as a JSON transcript to a cleanup-only prompt that must not answer or carry them out and keeps numbers as digits (`DictationCleanupPrompt`); Transcribe stays verbatim and bypasses the model and context providers. A writing request starts with a command (“reply…”, “napiši…”, after optional filler such as “hey” or “okay so”) or is a relay aimed at someone else that points at context (“tell him the time from the message above”); see `DictationRequestRouting`. The older focused-window OCR option remains separate and may begin during recording; unused OCR is cancelled after ASR, and the prompt keeps the window's last 2,000 characters. Last result shows which context a Compose request used, and a Writing profile row links to the profile Compose uses for tone and terminology. Source/permission changes reject stale results. See the [synthetic dictation quality replay](Benchmarks/Dictation/README.md).
- **Opt-in & private:** off by default; needs the Microphone grant plus Input Monitoring for the global shortcut. Audio, transcription, and paste all happen on-device.

## Agent Mode — an embedded coding agent on your selected Main LLM

- **A coding agent in the sidebar:** the **Agent** section embeds the pi coding agent, preconnected to the same local Main LLM through an OpenAI-compatible shim — a coding agent running on your own GGUF (or whichever backend you configured). A persistent task sidebar supports search, rename, pin, archive, and restore. Browsing saved tasks loads native Pi history without starting inference. Execution is limited to four live runtimes; idle saved tasks can release their runtime when another starts.
- **Conversation workspace:** a constrained reading column groups adjacent tool activity. Approvals remain above the composer, with the target and effect visible. The results inspector previews recorded output, proposed edits, and attached sources, with copy and local export. Copy, edit as follow-up, review and retry, and branch from message preserve the original conversation and do not undo completed actions.
- **Composer and context:** drag in files or use the context menu and `@` picker to attach UTF-8 documents, text-layer PDFs, meetings, and separately authorized saved moments. Sources are reread on send, with limits of 10 attachments and 60,000 total characters. Explicitly selected meetings are attached as summary/transcript text; screen sources include retained text and notes, never pixels. The model and inference destination remain visible.
- **Follow-ups:** while working, **Send now** uses Pi steering; **Queue follow-up** keeps an editable, cancelable host-side queue. Stop and app relaunch pause the queue. **Send next** explicitly resumes it. Failed sends retain their draft and attachments for review.
- **Navigation:** ⌘N creates a task, ⌘⇧F searches tasks, ⌘⌥←/→ moves between tasks, ⌘F finds in the current conversation, ⌘L focuses the composer, and ⌘⌥B toggles results. Agent actions and tasks also appear in the command palette. Text zoom is available in the Agent menu.
- **Persistence:** `agent/sessions/tasks.json` stores task metadata, drafts, queued follow-ups, and attachment references alongside native Pi JSONL conversations. The latter contain the context actually sent. Archiving preserves both; **Clear saved Agent history** removes both after confirmation. A branch copies the chosen native conversation ancestry to an independent file; it neither replays tools nor rolls back files.
- **Pi's own network behavior is disabled:** pi runs with `--offline`, version checks and crash reporting disabled. Enabling Agent Mode downloads its runtime once — a checksum-verified Bun release from GitHub plus the pi package from npm, pinned by a lockfile bundled with LokalBot. LLM requests stay local with the built-in backend; an approved remote Ollama or OpenAI-compatible endpoint receives agent context when selected.
- **Workspace boundary:** new tasks use a sibling working directory outside the private library. Saved tasks rooted inside the library retain their history and drafts but cannot execute. Raw reads of protected library, runtime, and session paths enter the tool-approval flow when a broader parent directory is selected; the selected approval mode still applies.
- **You approve sensitive access:** the extension's gate is an allowlist. A read inside the selected workspace and outside the private library is the only tool call that runs without asking; file and shell calls follow the selected approval mode. Any other tool (an MCP tool, codemode, or one a later Pi release adds) asks with its exact arguments in every mode except **Full access**, which approves every agent tool; it cannot be allowed for the session. Commands, and the arguments of tools without a dedicated preview, exceeding 65,536 JavaScript UTF-16 code units are rejected before approval; the host also rejects incomplete or truncated previews. Approved shell commands run with your macOS user permissions and may access files or the network.
- **Inference redirects:** native buffered/streaming HTTP requests follow redirects only within the original scheme/host/port. The Pi provider uses its own scoped fetch adapter that rejects all redirects and validates the initial origin. Configure a server's final endpoint directly; inference approval does not authorize forwarding prompts or credentials to a different origin.
- **Headless:** `LokalBot --agent "<prompt>"` runs one agent turn from the terminal (see Headless flags). It auto-approves file changes but safely declines shell and external-read requests because no person is present to review them.

## Screen context, OCR & privacy

- **Capture:** fresh settings select activity only; visible text and pixels require explicit opt-in and the applicable macOS grants. A bounded, single-flight Accessibility reader collects visible text first; Vision (`VNRecognizeTextRequest`, on-device) runs only when that text is too thin. Coarse triggers include app/window changes, clicks, typing pauses, settled scrolling, and pasteboard-generation changes, plus an idle-active fallback. The trigger monitor never reads raw keys, pointer positions, scroll deltas, or clipboard contents. Automatic work has a 20-second cooldown; byte-identical frames and unchanged text are skipped. Visual mode uses ScreenCaptureKit, downscales to ≤1500 px, encodes HEIC, and groups similar scenes with a 64-bit perceptual dHash.
- **Contextual privacy:** capture skips idle/lock/pause states, excluded apps and domains, and focused secure fields; private and incognito windows are captured like any other window. URL metadata drops credentials, query, and fragment; document metadata keeps only the filename. Deterministic rules redact captured text before persistence: credentials, including prefixed names (`DB_PASSWORD=`, `GITHUB_TOKEN:`), common provider token formats, and URL passwords, plus payment card numbers (issuer prefix and Luhn) and IBANs (mod 97). If either accessible text or OCR detects a credential, the redacted text remains useful but the pixel payload is never written.
- **Meetings:** visual context during recording is a separate opt-in. It is throttled to at most one automatic moment per minute and rows carry the active meeting id. Manual capture remains available.
- **Encryption & retention:** each retained visual is AES-GCM sealed with a per-install Keychain key. Pixels auto-delete after N days (default 14), and captured text follows the same retention unless you opt into keeping it forever. Saved moments retain their encrypted pixels, text, and semantic vector until unsaved or explicitly deleted. Accessibility-only and retention-pruned moments remain represented as text context rather than fake thumbnails.
- **Exclusions:** the comma-separated app list is preseeded with password managers, and the Passwords app, Keychain Access, 1Password, Bitwarden, and KeePassXC are skipped by bundle identifier whatever their name in the user's language or the list. A rule matches the app's display name; a rule with a dot also matches that bundle identifier and those beneath it, and **Choose App…** stores the bundle identifier; excluded time logs as "Private" with no title or context. Domain/URL-prefix rules apply to both text and pixels.

## Safe local routines

- **Curated jobs:** post-meeting follow-up, daily stand-up, weekly work log, unfinished-action rollup, and local journal. Each renderer has a fixed local read scope and accepts no arbitrary prompt, shell command, or network action.
- **Scheduling:** event-driven follow-ups run after processing; daily and weekly jobs catch up after wake. Meeting recording, dictation, cotyping generation, and the meeting pipeline take priority. Fixed calendar scopes and fingerprints of prepared output make corrections, completion, deletion, and reverted edits new durable revisions. Unchanged successful or failed revisions are terminal across relaunch; invalidation cancels stale work. Preparation and writing each have a 30-second bound.
- **Writes:** Markdown goes only under a user-selected destination with `0700` folders and `0600` files. Routines and daily exports share hash-sidecar ownership checks: unchanged output is idempotent, changed generated output is replaced only while its stored hash matches, and user edits or unrelated files are preserved. Legacy files without a sidecar can be adopted only when their bytes already equal the new output. Deterministic secret redaction is applied again before writing.

### Interface language

Choose **Settings → General → Appearance → App language** (or the picker in
first-run setup) to follow the system, use English, or use Simplified Chinese.
The choice is saved with app settings and updates open windows without a restart.
It does not change transcription or notes languages, model prompts, or saved content.
System mode uses the first supported language in the macOS preference list,
maps Chinese variants to Simplified Chinese, and falls back to English.

Interface translations live in `LokalBot/Resources/{en,zh-Hans}.lproj/Localizable.strings`.
SwiftUI and AppKit hosting roots use `appLanguageRoot(settingsStore)` to observe
the selected locale, including already-open dictation overlays and the UI test
host; app-owned dynamic labels explicitly
use `LocalizedStringKey`, while native menus use `AppLanguage.localized`.
Keep user content verbatim and add matching entries to both tables.
`AppLanguageTests` covers preference migration, persistence, language resolution,
bundled lookup, and translated settings search. `AppLanguageRootTests` verifies
live locale propagation and preserved content identity in offscreen hosting

### Settings categories

Everything lives in **Settings**, organized into searchable categories:

- **General** — launch at login, menu-bar-only mode, appearance (theme: Match System / Light / Dark; five text sizes applied through `AppFont` and the `\appTextScale` environment, since macOS text styles ignore SwiftUI Dynamic Type; Default renders body text at 14 pt, one point above macOS, and Small is the unscaled system size), the opt-in `⌃⇧Space` Quick Recall shortcut, permission status + repair, storage location, update checks.
- **Recording** — auto-record behavior, calendar-assisted detection, auto-transcribe/summarize, notes template + language, neural diarization, day tracking modes, scheduled Markdown/Obsidian/Logseq daily-memory export, and safe local routines.
- **Models** — readiness for the Transcribe, Think, and Autocomplete roles; recommended/lightweight presets; transcription engines; Main LLM backends (Built-in / Apple Intelligence / Ollama / OpenAI-compatible); the GGUF catalog and Hugging Face browser; embeddings; and Kokoro TTS.
- **Privacy** — screen-text retention plus independent meeting-library and time-scoped screen-memory MCP permission profiles.
- **Advanced** — unified Memory Health for capture and processing, the live resource monitor, hardware fit advice, retention controls, and Agent CLI installation.
- **Writing** — test and tune Autocomplete (the Cotyping engine, exclusions, acceptance behavior) and the writing profile. Category switches start at the top rather than inheriting another form’s scroll position.
- **Dictation** — its own category: the shortcut (recordable, including modifier-only chords), trigger style, paste vs. clipboard, the speech model, permissions, and a try-it-here rehearsal. Settings search jumps straight to it.

## Agent CLI & MCP

The optional [ChatGPT plugin](Distribution/chatgpt-plugin/README.md) adds a
meeting-only MCP adapter, an interactive panel and composer mentions, and a
public OAuth relay with per-Mac pairing. Its foreground companion delegates
all reads to the embedded CLI's existing permission gate. The plugin has its
own Node build, protocol tests, and isolated native CLI integration workflow;
see its README and [launch runbook](Distribution/chatgpt-plugin/docs/DEPLOYMENT.md).
No public endpoint or installed companion is created by building the app.

The stdio reader must answer newline-delimited requests while stdin stays open.
It uses a bounded POSIX read because Foundation's `read(upToCount:)` can wait
to fill a pipe buffer, blocking interactive MCP handshakes. The native
integration test and plugin fixture test cover the live-pipe behavior.

`lokalbot-cli` (ArgumentParser, embedded in `Contents/Helpers/`) gives coding agents read-only access to the meeting library via `list` / `get` / `search` / `actions` / `people` / `path`. `actions` and `people` share the app's outcome projection, thread clustering, due-date resolution, and People rules (the CLI target compiles those model files). JSON by default, `--table` for humans. Settings → Advanced → Agent CLI (or `lokalbot-cli install-skill`) symlinks the binary to `~/.local/bin/lokalbot-cli` and the bundled skill to `~/.agents/skills/lokalbot-cli/`.

The same binary is an **MCP server**: `lokalbot-cli mcp` speaks MCP over stdio. Meeting tools are `list_meetings` / `get_meeting` / `search_meetings` / `ask_library` / `get_action_items` / `list_people` / `get_person`; people tools return names only, never attendee addresses. Independently gated screen tools are `search_screen` / `get_timeline` / `get_recent_activity` / `get_app_usage` / `get_screenshot_detail`; they use a query-only SQLite connection and return captured text/metadata, never decrypted pixels or file paths. The screen marker stores one of three profiles: today, rolling seven days, or all retained history; every query is clamped and out-of-scope detail ids appear missing. LokalBot does not upload library content, but an external MCP client may transmit tool inputs and results under its own privacy terms.

Both agent surfaces are **off by default**. Meeting tools require `control/agent-access-enabled`; screen-memory tools require the separate JSON `control/screen-memory-access-enabled` marker. Neither marker grants the other capability. Empty markers written by older builds retain their prior unscoped authorization until the user chooses a profile; newly enabled access defaults to seven days.

See [`.agents/skills/lokalbot-cli/SKILL.md`](.agents/skills/lokalbot-cli/SKILL.md).

## Testing

- **Unit** (`LokalBotTests`, in-process):
  ```bash
  xcodebuild -project LokalBot.xcodeproj -scheme LokalBot -destination 'platform=macOS' test
  ```
  Pure-logic coverage — prompt sanitizers, search ranker, model fit, transcript merging, settings codecs, data migration, and the chat agent (tool-call parsing for JSON **and** native function-call forms, the ReAct loop, observation formatters).
  Select an affected class or method with `-only-testing:LokalBotTests/CotypingTests` (replace the class with the relevant test).
- **Qwen upgrade parity:** `QwenASREngineTests/testCachedModelTranscriptionMatchesReferenceWhenProvided` uses cached weights from `LOKALBOT_QWEN_TEST_MODEL_DIR` and a `LOKALBOT_QWEN_TEST_REFERENCE` JSON array of `{id, audio, language, text}` records. Use public or synthetic audio, with `text` captured from the previous pinned runtime. It checks the production decode entry point with both repetition policies; `LOKALBOT_QWEN_TEST_REPORT` optionally writes the decoded outputs. Prefix these environment variables with `TEST_RUNNER_` when invoking `xcodebuild` so they reach the test host. Regular unit runs skip this hardware check without a fixture.
- **Anthropic API:** `AnthropicEngineTests` covers the native Messages API requests offline. `AnthropicLiveTests` sends synthetic text to Anthropic only when `TEST_RUNNER_ANTHROPIC_API_KEY` is set (`TEST_RUNNER_LOKALBOT_ANTHROPIC_MODEL` overrides `claude-sonnet-5-5`): it checks that the meeting-notes schema is accepted, that repeated context is read from the prompt cache, and that streaming completes.
- **Audio crash probe:** `bash Scripts/tests/audio-recovery-crash.sh` kills a synthetic writer with SIGKILL, removes its growing CAF, and verifies waveform/frame coverage from checkpoints without capture devices or a private library. The hosted unit job also runs it, beside the unit tests.
- **Agent runtime:** `LOKALBOT_PINNED_RUNTIME_ROOT=/path/to/agent-runtime bash Scripts/tests/run-pi-runtime-tests.sh` runs the extension and adapter tests against the pinned runtime. It copies test sources to a temporary folder and uses synthetic loopback services without changing the installed runtime.
- **UI** (`LokalBotUITests`, XCUITest): run the hosted **UI Tests** workflow or another remote Mac runner. `Scripts/ui-tests.sh --remote` dispatches the suite; append a test name to select one test. Never use `--foreground` or run UI tests locally on this MacBook. The script checks that the relevant changes are committed and pushed so the remote runner tests the intended revision. It drives a dedicated UI Test Host against a synthetic library under a temporary `LOKALBOT_STORAGE_ROOT`; `LOKALBOT_UI_TEST=1` skips side-effectful subsystems, so the suite never touches the installed production app.
- **Documentation captures:** `Scripts/capture-screenshots.sh --stills-only` builds the same isolated host, seeds synthetic data, and renders fixed-density PNGs in-process. This is a capture pass, not the XCUITest suite; see [Docs/screenshot-kit.md](Docs/screenshot-kit.md).
- **End-to-end** (`Scripts/e2e.sh`): exercises real audio, CoreML transcription, the bundled llama-server, and SQLite via the headless flags; skips flows needing ungranted permissions.
- **Scripts and lint:** `python3 -m unittest discover -s Scripts/tests` covers the CI helpers, seed profiles, trace checker, and drift report; `swiftlint lint --strict --quiet` must exit 0. CI runs SwiftLint 0.65.1 from its official Linux image (`.github/workflows/lint.yml`); install the same version locally to match.
- **Model scenarios:** `LokalBotTests/Fixtures/stub-openai.ts` is an OpenAI-compatible stub (Bun, pinned by `Scripts/ci/fetch-bun.sh`; point `LOKALBOT_TEST_BUN` at it locally) that answers each request by its system-prompt marker (`LokalBotTests/Support/ModelRequestPurpose.swift`) and can truncate, stall, drop, or send malformed or reasoning-heavy replies. `ModelServerScenarioTests` drives the real engine and generators through it. `LokalBotTests/Fixtures/model-recordings/` holds real GLM 5.3 Flash and Qwen3.8 Flash answers to synthetic prompts; `ModelReplayTests` replays them and `ModelBudgetGuardTests` fails when a recorded answer no longer fits our token budgets. The nightly `Model drift` job records fresh answers (OpenRouter, the only two models, at most 40 requests) and uploads them as the `model-recordings` artifact; refresh the committed recordings from that artifact in a normal PR after reading every answer.
- **Capture replay:** capture, activity tracking, and meeting detection read every OS boundary through `CaptureEnvironment` (`LokalBot/Services/Capture/`). `ReplayCaptureEnvironment` answers from a trace in virtual time; traces live in `LokalBotTests/Fixtures/capture-traces/` and `CaptureReplayTests` runs the real services on them. Record a trace with a Debug build's `--record-capture`, the Debug menu's **Record Capture Trace**, or `Scripts/record-capture/run.sh chrome|safari` (launches a browser and the app — ask first). Traces are scrubbed before they are written, and CI's `check-capture-recordings.py` rejects any unscrubbed trace. **Every escaped capture bug gets a trace (scripted, or reconstructed by hand in scrubbed form) and a replay test that fails with the fix undone.**
- **Day in the life:** `LOKALBOT_APP=<Debug build> LOKALBOT_TEST_BUN=<bun> bash Scripts/day-in-the-life.sh` seeds one untranscribed workday (`Scripts/seed_demo_library.py --profile full-day`), transcribes it from golden transcripts, writes notes and the digest through the model stub, reviews a meeting boundary, searches meetings and screen text, and runs the health checks (digest coverage at least 60%). It launches the app headless; on failure it keeps the library for inspection. On every PR the unit-test job runs it beside the unit tests, and the `Day in the life (macOS)` check reports its result; the nightly run repeats it with real Parakeet (`--real-asr`). Recorded notes answers quote the golden wording, so the real-ASR run checks the day's word error rate against the golden transcripts (case, punctuation, hyphens, and split or joined compounds ignored; at most 10% across the day's meetings, so one misheard word in a short meeting cannot decide the run) and that the design review's notes finish, instead of the quoted owner. A failed nightly run uploads its library as the `day-in-the-life-real` artifact.
- **UI background shard:** `BackgroundFlowUITests` runs the UI Test Host with its background work on (`LOKALBOT_UI_TEST_BACKGROUND=1`, a replayed trace, file audio, golden transcripts, and the model stub). `Scripts/ci/ui-shards.py` gives it its own `background` shard, and the aggregate XCUITest gate requires it. Hosted CI only, like every UI test.
- **Upgrade fixtures:** the `Upgrade fixtures` workflow seeds a library with each release's own seed script, opens it with that release's signed build on a clean hosted Mac, and uploads the library, defaults, and synthetic test keys. After a release, add the new version to `Scripts/upgrade-fixtures/settings.py` and the workflow matrix, run the workflow, and commit the new fixture.
- **Nightly:** `.github/workflows/nightly.yml` runs model drift, the real-Parakeet workday, and scale checks (a 180-day library, a digest while activity is written, two copies on one library). It never blocks a PR; failures open or update an issue.
- **Health checks:** Debug builds evaluate yesterday at 09:00 (and on the next launch if that was missed) and post a notification that opens the report on failure. `LokalBot --health` runs the same checks on demand. Reports are written to `diagnostics/health/YYYY-MM-DD.{json,md}` in the library. Settings → Advanced → System has **Run Health Check Now** and **Export Diagnostics…**.


Rooted at the bundle id (not "LokalBot") so it never collides with another app's `Application Support/LokalBot` on the default case-insensitive filesystem.

Legacy migration never replaces an existing current database, including an empty one. A missing database is imported through a WAL-aware SQLite snapshot and atomic no-replace installation; concurrent creation wins safely. Conflicting legacy data and recovery snapshots remain available for explicit reconciliation. Dev, UI-test, and fixture launches skip legacy migration.
