# LokalBot for Android

The phone, tablet and foldable companion to LokalBot on the Mac. It reads
the Mac's shared meetings, actions, Timeline, Day Digests, people and projects,
and asks the Mac questions. Data moves only over the local network or
Tailscale, end-to-end encrypted, through the Rust sync core
(`LinuxWindows/crates/lokalbot-sync`). The plan is
[Docs/companion-apps-plan-2026-10-30.md](../../Docs/companion-apps-plan-2026-10-30.md);
the wire contract is in [Companion/protocol](../protocol).

- `app/`: the app, `me.dotenv.lokalbot.companion` (Kotlin, Compose, Material 3 Adaptive).
- `sync/`: packages the Rust core and its UniFFI Kotlin bindings from
  `sync/build/rust`, which `Scripts/build-sync-android.sh` writes.
- `app/.../ui/theme/LokalBotTokens.kt` is generated by
  `node Companion/design/generate.mjs`; don't edit it.
- The sample library ("Try it without a Mac") is
  `Companion/protocol/fixtures/sample-library.json`, copied into the APK at
  build time.

## Prerequisites

- JDK 21.
- Android SDK with platform 37 (compileSdk; targetSdk is 36), platform-tools
  and an NDK (r29 is tested). Set `ANDROID_HOME`, or `sdk.dir` in
  `local.properties`.
- Rust through rustup. The toolchain is pinned in
  `LinuxWindows/rust-toolchain.toml`. You also need the
  `aarch64-linux-android` and `x86_64-linux-android` targets and
  `cargo-ndk`; the build script installs whichever is missing.

## Build and test

Heavy builds run on the Ubuntu box, not the MacBook (see AGENTS.md).

```sh
Scripts/build-sync-android.sh       # from the repo root; does nothing when its inputs are unchanged
cd Companion/android
./gradlew :app:assembleDebug        # app/build/outputs/apk/debug/app-debug.apk
./gradlew :app:testDebugUnitTest    # JVM and Robolectric tests
./gradlew :app:verifyRoborazziDebug # screenshots against app/src/test/screenshots
./gradlew :app:recordRoborazziDebug # re-record them after an intended UI change
./gradlew :app:lintDebug
```

`./gradlew clean` deletes `sync/build/rust` along with the rest of the build
output. Run `Scripts/build-sync-android.sh` again afterwards.

CI runs the same steps in `.github/workflows/companion-android.yml`.

`ssh ubuntu@ovhcloud-ubuntu-ns3088369` has:

- `openjdk-21-jdk-headless` from apt;
- `~/android-sdk` with:
  - cmdline-tools;
  - platforms `android-36` and `android-37.0`;
  - build-tools 36.0.0 and 36.1.0;
  - platform-tools;
  - NDK 29.0.14206865;
  - the emulator and `system-images;android-36;google_apis;x86_64`;
- `~/.profile` exporting `JAVA_HOME`, `ANDROID_HOME`, `ANDROID_SDK_ROOT`,
  `ANDROID_NDK_HOME` and the SDK tools on `PATH`;
- the Rust Android targets, and `cargo-ndk` in `~/.cargo/bin`.

To build there:

1. Copy `Companion/`, `Scripts/build-sync-android.sh` and `LinuxWindows/`
   (without `target/`) to a directory under `~/offload/`, keeping their
   relative paths.
2. Run the commands above in a login shell (`bash -lc`).
3. Copy changed sources back, and delete the copy when you're done.

The box has KVM, so a headless emulator works:

```sh
avdmanager create avd -n lokalbot-pixel -k "system-images;android-36;google_apis;x86_64" -d pixel_7
emulator -avd lokalbot-pixel -no-window -no-audio -gpu swiftshader_indirect &
```

## Install on a phone

Turn on USB or wireless debugging, then run
`adb install -r app/build/outputs/apk/debug/app-debug.apk`. The APK carries
arm64-v8a and x86_64 only.

## Pair

**With the Mac app.**

1. On the Mac, open Settings → Phones & tablets → Add a device.
2. On the phone, tap Pair with your Mac, then scan the code or paste the
   link.
3. Check the device name the Mac will show, and tap Pair.
4. Allow the device on the Mac.

Both devices need the same Wi-Fi, or Tailscale.

**With the stand-in host** (no Mac needed). From `LinuxWindows/`:

```sh
cargo run -p lokalbot-sync --example companion_host -- --name "Dev Mac"
```

The host serves the sample library, which it compiles in from the fixture,
and prints a pairing QR code and link.

- Optional flags: `--auto-approve`, `--port 17890`, `--dir PATH` and
  `--loopback`.
- While it runs, type `pair`, `devices`, `remove <id>`, `publish` or `quit`.
  Answer a pairing request with `y` or `n`.

On a real phone, the host's machine must be reachable over the LAN or
Tailscale. For the emulator, start the host with `--loopback`, then forward
the port and open the link:

```sh
adb reverse tcp:17890 tcp:17890
adb shell am start -a android.intent.action.VIEW -d "lokalbot://pair?d=…" me.dotenv.lokalbot.companion
```

## Release

- **Builds.** Release builds use R8; the JNA and UniFFI keep rules are in
  `sync/consumer-rules.pro`. Signing configuration stays out of the repository.
  Build with `./gradlew :app:bundleRelease`.
- **Testing.** Ship through Play internal testing first, then production.
- **Play review.** Reviewers can't pair with a Mac. The review notes should
  send them to **Try it without a Mac** on the first screen, and explain the
  Mac app, the local network and Tailscale.
- **Data safety.** LokalBot collects nothing; data stays on the person's own
  devices.
- **targetSdk 37.** At 37, local network access needs the runtime permission
  `ACCESS_LOCAL_NETWORK` (in the Nearby devices group). Declare it, and
  request it before discovery and connecting (or use NSD's system picker),
  when raising targetSdk. Until then the app targets 36, where `INTERNET`
  covers local network access.
